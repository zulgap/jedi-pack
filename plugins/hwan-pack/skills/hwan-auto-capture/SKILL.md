## 언제 쓰나

- 고객 테이프를 캡처 장치로 디지털화할 때. 테이프 한 개당 한 번
- "녹화 시작" · "테이프 자동 녹화" · "캡처 돌려줘" · "테이프 넣었어" · "다음 테이프"

## 무엇이 필요한가

- ffmpeg (한 번만) — 윈도우: `winget install Gyan.FFmpeg` → 터미널 새로 열기
- USB 캡처 장치가 꽂혀 있고 VCR 이 그 장치에 연결돼 있을 것
- 설정 파일 `~/.claude/zulgap/hwan-capture.json` — 장치 이름 2줄. 처음 한 번 `--list` 로 찾아 적는다:
  ```
  node <이 스킬 폴더>/scripts/auto-capture.js --list
  ```
  → 나온 영상·음성 장치 이름을 그대로 파일에 넣는다 (도구가 채워 넣을 JSON 을 찍어 준다)
- 디스크 여유: 녹화 원본은 무손실이라 **1시간 ≈ 8~9GB**. 변환 뒤 원본은 사람이 지운다

## 어떻게 하나

🔴 **시작은 언제나 이 스킬에서** — 테이프를 넣는 것으로 시작하지 않는다. 넣은 테이프는 어디쯤 멈춰 있는지 모르고,
넣자마자 저절로 재생되는 VCR 도 있어 그대로 녹화하면 **중간부터 찍힌다** (사장님 확정 2026-09-23).

1. 사용자에게 **저장 폴더**와 (있으면) **고객명**을 받는다
2. 먼저 `--dry` 로 장치·출력 경로·명령을 보여준다. 설정 파일이 없으면 여기서 멈추고 `--list` 절차를 안내한다
3. 🔴 **되감기 확인** — "테이프를 처음까지 되감으셨나요?" 라고 묻는다. 「네」라는 답을 받기 전에는 실행하지 않는다.
   도구도 `--rewound` 가 없으면 시작을 거부한다(이 질문을 건너뛰지 못하게)
4. 「네」를 받으면 **백그라운드로** 실행하고 "재생을 누르세요 — 뜨는 작은 창으로 화면을 보실 수 있습니다" 라고 말한다 (녹화는 테이프 길이만큼 걸린다):
   ```
   node <이 스킬 폴더>/scripts/auto-capture.js --out "<폴더>" --name "<고객명>" --rewound
   ```
   - 볼 화면 창(ffplay): 대기 때부터 들어오는 화면이 작은 창에 뜬다 — 재생을 누르는 순간 시작 부분인지 눈으로 본다.
     🔑 **창을 닫아도 녹화는 계속된다**(창은 구경용). 창이 필요 없으면 `--no-view`
   - 대기: 화면·소리가 들어올 때까지 기다린다 (파일 안 만듦)
   - 녹화: 들어오는 순간 무손실(mkv)로 받는다. 5분마다 진행을 찍는다
   - 종료: 검정 화면 30초 **그리고** 무음 30초가 이어지면 테이프 끝으로 보고 스스로 멈춘다
   - 변환: 멈추자마자 hwan-vhs-to-mp4 스킬의 스크립트를 불러 같은 폴더에 mp4 를 만든다
5. 🔴 **첫 장면 확인** — 녹화 10초쯤 뒤 `첫 장면: <…_first.jpg>` 줄이 찍힌다. 그 사진을 열어(Read) 사용자에게 보여주고
   "테이프 시작이 맞나요?" 라고 묻는다 (볼 화면 창으로 이미 확인했으면 그 답으로 갈음 · 사진은 자리를 비운 경우의 기록)
   - **맞다** → 그대로 둔다. 끝까지 알아서 간다
   - **아니다** → 도구가 알려준 `<출력>.stop` 파일을 만든다(빈 파일). 녹화가 멈추고 변환은 안 한다.
     그 mkv·jpg 는 사용자가 「지워라」 하면 지우고, 되감은 뒤 3번부터 다시
6. `ok <이름>_mp4.mp4 …` 가 찍히면 끝. 사용자에게 파일 위치와 걸린 시간을 알린다
7. 다음 테이프면 3번부터 다시

🔴 **멈출 때는 `.stop` 파일로** — 백그라운드 작업을 그냥 끄면 윈도우에선 ffmpeg 가 살아남아 녹화를 계속한다.
녹화는 신호가 들어온 순간부터 이미 되고 있으므로 5번 확인을 기다리는 동안 앞부분이 잘리지 않는다.

## 사람이 봐야 하는 곳

- **테이프 넣기·되감기·재생 누르기** — 이것만 사람이 한다. 🔴 VCR 을 자동으로 조작하지 않는다(사장님 확정 2026-09-23)
- **「처음까지 되감았나」와 「첫 장면이 시작 맞나」** — 두 번 다 사람이 답한다. AI 가 사진만 보고 「시작 맞다」고 판정하지 않는다
- **첫 파일 1개는 재생해서 확인** — 앞부분이 잘렸는지(대기 판정이 늦었나), 끝이 너무 일찍 끊겼는지(중간 검정 장면)
- 「신호를 받지 못한 채 끝났습니다」가 뜨면 케이블·장치·VCR 출력을 사람이 본다

## 하면 안 되는 것

- 🔴 VCR 재생·정지를 코드로 보내지 않는다 — 적외선 송신기 붙이자는 제안도 하지 않는다(보류 아님, 안 한다)
- 임계값(검정 30초·무음 30초·검정 판정 0.98·무음 -50dB)을 대화 중에 바꾸지 않는다 — 바꾸려면 설정 파일에 적고 이유를 남긴다
- 원본 mkv 를 자동으로 지우지 않는다 — 고객에게 mp4 를 넘긴 뒤 사람이 지운다
- 녹화 파일을 서버·클라우드로 올리지 않는다

## 다 됐는지 확인하는 법

- 도구가 「테이프 끝 감지 → 녹화 종료 N.NNGB (M분)」 다음에 변환 스크립트의 `ok …_mp4.mp4` 를 찍는다. 둘 다 있어야 끝
- 순수 함수 검사: `node scripts/_test-auto-capture.js` → `16/16`
- 실제로 돌려본 결과: 2026-09-23 사장님 PC 에는 캡처 장치가 없어, 녹화 명령의 입력만 합성 영상(20초)으로 바꿔 ffmpeg 로 실제 실행 — mkv 20.0초 전체 + 10초 지점 첫 장면 사진 1장이 함께 나왔다(사진을 찍고 나서도 녹화가 계속됨 확인).
  같은 날 v1.2: 볼 화면을 켠 채 합성 입력으로 돌려 ① 볼 화면이 곧바로 흐름(5초에 75MB) ② 4초에 창을 강제로 닫아도 녹화 계속 ③ 12초 판정에서 스스로 멈춤(12.9초)을 확인.
  🔴 그 과정에서 **v1.0~1.1 의 `-nostdin` 때문에 멈춤 신호가 무시되던 결함**을 발견해 고쳤다 — 실제 테이프였으면 「신호 대기」에서 영원히 안 넘어갔다 **담당자 PC 에서 첫 테이프 1개 무인 녹화 뒤 이 줄을 갱신할 것** — 특히 「끝 감지」가 실제 테이프 끝(파란 화면·무신호)에서 잘 걸리는지

## 함정

- **끝 감지가 안 걸리는 테이프**: 끝에 화면 노이즈(눈·지지직)가 나오는 VCR 은 「검정」이 아니라 계속 녹화된다 → Ctrl+C 로 끝내고 mp4 변환은 따로. 이런 VCR 이면 설정의 `black_pic_th` 를 낮추지 말고 사장님께 알린다(다른 판정축이 필요)
- **앞부분 잘림**: 대기 → 녹화 전환에 1~2초가 든다. 재생 누르고 5초쯤 뒤에 본편이 시작되는 테이프가 대부분이라 문제 없지만, 첫 파일은 확인
- **중간 검정+무음 30초가 넘는 장면**(정지·빈 구간)이 있으면 거기서 끝난 것으로 본다 → 나머지는 「다음 테이프」로 한 번 더 돌려 파일 2개
- 모노 출력 VCR(SV-65D)은 한쪽 소리만 들어온다 → 변환 단계는 그대로 두고, 납품 전 사람이 확인

## 막혔을 때

| 증상 | 조치 |
|---|---|
| `장치 설정이 없습니다` | `--list` → 설정 파일에 이름 적기 |
| `--list` 에 장치가 안 나옴 | 캡처 장치 드라이버가 DirectShow 를 안 내놓는 것 → 이 스킬 불가. 캡처 프로그램으로 녹화하고 hwan-vhs-to-mp4 로 변환만 |
| 녹화 중 `rtbufsize` 경고 | USB 대역 부족. 다른 USB 장치를 빼고 다시 |
| `신호를 받지 못한 채 끝났습니다` | 케이블·VCR 출력 확인. 대기는 무한이라 이 메시지는 Ctrl+C 나 장치 분리 때만 |
