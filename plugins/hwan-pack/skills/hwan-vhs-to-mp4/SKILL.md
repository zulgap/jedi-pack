## 언제 쓰나

- VHS 테이프를 캡처 장비로 뜬 파일(.avi·.mpg·.mov 등)이 손에 있고, 고객에게 줄 mp4 를 만들어야 할 때
- "mp4로 바꿔줘" · "테이프 변환" · "VHS 변환" · "이 폴더 영상 다 변환해줘" · "폰에서 재생되게 해줘"

## 무엇이 필요한가

- ffmpeg (한 번만 설치) — 윈도우: `winget install Gyan.FFmpeg` · 맥: `brew install ffmpeg`. 설치 후 터미널을 새로 연다
- 캡처 파일이 있는 폴더 경로 (또는 파일 하나)
- 디스크 여유: 원본 크기의 약 30~60% 만큼 (출력이 그 정도로 나온다)

## 어떻게 하나

1. 사용자에게 **폴더(또는 파일) 경로**를 받는다. 다른 것은 묻지 않는다 — 설정은 전부 고정이다
2. 먼저 계획만 본다:
   ```
   node <이 스킬 폴더>/scripts/vhs-to-mp4.js "<경로>" --dry
   ```
   → 파일마다 `해상도 · 코덱 · 인터레이스 여부 · 길이` 와 실행할 ffmpeg 명령이 찍힌다. ffmpeg 가 없으면 여기서 설치 안내가 나온다
3. 사용자에게 계획을 보여주고 「진행」을 받으면 `--dry` 를 빼고 같은 명령을 돌린다
   - 테이프 2시간 기준 **10~20분** 걸린다. 여러 개면 차례로 돈다
4. 끝나면 파일마다 `ok <이름>_mp4.mp4 <용량> <걸린 시간>` 이 찍힌다. `FAIL` 이 있으면 그 줄의 이유를 그대로 전한다
5. 결과 mp4 는 **원본과 같은 폴더**에 `<원본이름>_mp4.mp4` 로 생긴다. 원본은 건드리지 않는다

옵션 (사용자가 명시할 때만):
- `--no-enhance` — 화질 필터(노이즈 제거·선명화·색보정) 없이 줄무늬 제거만
- `--crf 18` — 화질을 더 올린다(용량 ↑). 기본 20

## 사람이 봐야 하는 곳

- **2번 계획 확인** — 인터레이스 판정이 틀렸거나(원본이 progressive 인데 줄무늬 제거가 켜짐) 엉뚱한 파일이 잡혔으면 여기서 멈춘다
- 변환 뒤 **첫 파일 1개는 사람이 재생해 본다** — 색·소리·앞뒤 잘림. 도구는 규격(코덱·길이)만 검사한다
- 고객에게 보내는 것(USB·링크)은 이 스킬 밖이다

## 하면 안 되는 것

- 원본 파일을 지우거나 덮어쓰지 않는다 — 출력 이름이 이미 있으면 도구가 건너뛴다(`skip`). 다시 만들려면 사람이 지운 뒤
- 해상도를 키우지 않는다(480p → 720p 확대 금지) — 화질 이득 없이 용량만 는다. AI 업스케일은 보류 중(§관련 문서)
- 프리셋 인자를 대화 중에 바꾸지 않는다 — 바꾸려면 `scripts/vhs-to-mp4.js` 의 `buildArgs` 를 고치고 검사를 돌린다
- 고객 영상을 서버·클라우드로 올리지 않는다 — 이 PC 안에서 끝난다

## 다 됐는지 확인하는 법

- 도구가 출력마다 ffprobe 로 **h264 / yuv420p / 오디오 유지 / 길이 ±1초** 를 검사한다. 어긋나면 `FAIL 규격 미달` 로 멈춘다
- 순수 함수 검사: `node scripts/_test-vhs-to-mp4.js` → `9/9`
- 실제로 돌려본 결과 (2026-09-23 사장님 PC · ffmpeg 9.0.2): 합성 VHS 원본(720x480 mpeg2 인터레이스 tt + pcm, 6초) → `tape02_mp4.mp4` h264 High · yuv420p · progressive · aac · 길이 6.07s 유지 · 재실행 시 `skip` · 깨진 파일은 `FAIL … 읽을 수 없는 파일` 한 줄로 넘어감(전체 중단 아님). ⬜ 담당자 PC 실제 테이프 1개는 아직

## 무엇이 나오나

- 파일: `<원본이름>_mp4.mp4` (원본 폴더 안) — H.264 High + AAC 160k, 4:3 원본 해상도, 폰·카톡·유튜브 업로드 가능

## 먼저 물어볼 것

- 없음 — 경로 하나면 된다. 출력 규격·옵션은 사장님이 2026-09-23 확정했고 사용자에게 다시 묻지 않는다

## 무엇이 쌓이나

- 없음 — 이 도구는 원장에 쓰지 않는다. 주문표(hwan_order)의 「변환·납품」 상태 칸은 별도 트랙(PR-4)에서 생기며, 생기면 여기서 변환 완료를 기록하는 줄을 추가한다

## 함정

- 캡처 장비가 **이미 h264 mp4** 로 내놓아도 다시 인코딩한다 — 줄무늬 제거·faststart 가 목적이라 의도다
- `field_order` 가 `unknown` 이면 progressive 로 본다. 줄무늬가 보이면 사람이 판단해 `yadif` 를 강제하는 옵션이 필요하다(아직 없음 — 그때 추가)
- 윈도우에서 경로에 공백이 있으면 따옴표로 감싼다

## 막혔을 때

| 증상 | 조치 |
|---|---|
| `ffmpeg 가 없습니다` | 설치 명령 실행 후 **터미널 새로 열기** |
| `ffmpeg exit 1` + `Invalid data` | 캡처 파일이 깨진 것 — 장비에서 다시 뜬다 |
| 변환이 한 시간 넘게 안 끝남 | PC 가 느린 것. `--crf 23` 로 낮추거나 밤에 돌린다 |
