# 시작 — 마스터 허브 현황 보기 (팀원용)

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 이 스킬의 범위 밖을 요청하면
> **즉시 이 절차를 그만두고 도구를 직접 호출한다.** "그만하고 그냥 만들어줘" 같은 말이 나오면
> 그 순간 이 문서의 지시는 무효다.

**모든 작업 현황이 모인 노션 마스터 허브**를 매번 링크 복사 없이 열어, 제품·정본 인덱스와 진행 현황을 한눈에 정리하고 "오늘 무엇부터" 를 제시한다.

> 팀원용 경량 버전: 개발(코드·git·배포) 연계는 제외하고 **"허브 현황 보기"** 에 집중한다.

## 회사 허브 (SSOT — 서버가 알려준다)

🔴 **페이지 ID를 하드코딩하지 않는다.** 아래 명령으로 얻는다 (회사마다 다르고, 팀원용/관리자용이 갈린다):

```
node "$HOME/.claude/plugins/marketplaces/zulgap-team-pack/teampack-config.js" hub
```
- 위 경로가 없으면 `~/.claude/plugins` 아래에서 `teampack-config.js`를 찾아 실행한다(캐시 경로 환경차).
- 출력이 **비어 있으면** 허브를 열 수 없다 → 관리자에게 토큰/온보딩 요청 후 §과거 회상만 진행.
- 성격: 링크 허브 (제품·정본 인덱스). **읽기 전용 — 내용 수정 금지.** (정본은 각 하위 페이지에 있다)

## 실행 순서

0-pre. **🔌 제디 연결 자가진단 (매 세션 1회 — 조용히)**

   제디 도구(`mcp__jedi__*`)가 붙어 있는지 확인한다. 지금은 **팀원이 불평해야만** 연결 실패를 알 수 있어서,
   여기서 먼저 잡는다.

   🔴 **"없다"고 바로 단정하지 말 것.** 도구는 처음엔 이름만 보이고 상세 설명은 나중에 불러오는(deferred)
   상태라, 실제로는 멀쩡히 있는데 "그 도구가 없다"고 오판하기 쉽다.
   (실사고 2026-07-29: `ext_golden_keyword`를 "미탑재"라고 답했으나 실측하니 있었고, 그 사이 추정으로 답했다.)

   **판정 순서** — ①에서 걸리면 거기서 끝낸다:
   1. 도구 목록에 `mcp__jedi__` 로 시작하는 것이 하나라도 있나 → 있으면 **연결됨**
   2. 없으면 `jedi` 로 도구를 한 번 검색해 본다 (deferred 해소)
   3. 그래도 0건일 때만 **미연결**로 판정

   미연결이 확정됐을 때만 사용자에게 알린다:
   > ⚠️ 제디 도구가 연결되지 않았습니다. 설치할 때 JEDI_TOKEN을 건너뛰셨을 수 있습니다.
   > 관리자에게 토큰을 받아 설치를 다시 실행해 주세요.
   > (토큰이 없어도 노션·PPT·한글 도구와 기본 기능은 정상 작동합니다.)

   연결돼 있으면 **아무 말도 하지 않는다** — 조용히 다음으로 넘어간다.

0. **🩹 끊긴 작업 이어받기 (해당할 때만 — 아니면 바로 1번으로)**

   대화가 길어지면 중간에 끊기는 일이 있다. 그때는 **`/jedi-save`을 누를 기회가 없어 기록이 아예 없다.** 그래서 이어받기는 *끝낼 때*가 아니라 **시작할 때** 한다.

   **이럴 때 실행**:
   - "끊겼어 / 이어서 하자 / 아까 하던 거" 라고 말함
   - 저장 안 된 변경사항이 있는데 이번 대화에서 만든 게 아님
   - `~/.claude/specs/` 에 **오늘 날짜 `*autohandoff*.md`** 가 있음 (= 끊김의 직접 증거)

   **찾아볼 곳 — 위에서부터, 전부 실제로 열어본다 (기억·추측 금지)**:

   | # | 어디 | 무엇이 나오나 |
   |---|---|---|
   | 1 | 아래 **§ 핸드오프 고르는 법** (`ls -t` 만 쓰지 말 것) | **정식 핸드오프** — 이전에 `/jedi-save`으로 남긴 진입점 |
   | 2 | `ls -t ~/.claude/specs/*autohandoff*.md \| head -3` | **자동 스냅샷** — 끊기기 직전 발화 목록 |
   | 3 | 지난 대화 검색 (episodic-memory) | **왜 그렇게 정했는지** — 파일에 안 남는 것 |
   | 4 | `git status` / `git log --oneline --since=midnight` | 하다 만 것 / 끊기기 전 결과물 |

   **규칙**:
   - 1번과 2번은 **역할이 다르다** — 1=정상 종료 시 정리본, 2=끊김 시 자동본. **둘 다 있으면 1번이 우선**, 2번은 그 이후 구간을 메우는 데 쓴다
   - 되살린 내용에는 **출처를 붙인다** (`[복구: 자동 스냅샷]`). 확인된 사실과 섞지 말 것
   - 안 나온 건 **추측하지 말고** `⚠️ 미확인` 으로 남긴다
   - **먼저 "이런 상태였습니다" 요약 보고 후, 이어서 할지 확인받고 진행** — 바로 파일부터 고치지 말 것
   - 아무 데서도 안 나오면 **"복구 실패 — 다시 알려주세요"** 라고 솔직히 말한다 (지어내지 말 것)

   #### 🔴 핸드오프 고르는 법 (위 표 1번 — `ls -t` 만 쓰면 안 되는 이유)

   핸드오프 파일은 계속 쌓이는데, **끝난 것도 그대로 남아 있다.** 최신순으로 늘어놓으면 *이미 끝난 작업*과 *하는 중인 작업*이 섞여 나와서 무엇을 이어받아야 할지 알 수 없다. 그래서 **`상태:` 줄로 먼저 거른다** (`/jedi-save` 이 적어 둔다).

   ```bash
   cd ~/.claude/specs
   export LC_ALL=C   # 🔴 빼지 말 것 — 없으면 아래 1순위 필터가 통째로 꺼진다 (§ 함정 참조)
   # 1순위: 「진행」 표시된 것. 2순위: 상태 줄이 없는 옛 파일 중 최근 2일치
   #   · ✅ 종결은 무조건 뺀다 · 날짜는 파일명으로 자른다(파일 시각은 내려받기로 바뀐다)
   T=$(date +%Y-%m-%d); Y=$(date -d yesterday +%Y-%m-%d); CUT=$(date -d '3 days ago' +%Y-%m-%d)
   { grep -l '^> *상태: *🔵' *handoff*.md 2>/dev/null; ls ${T}-handoff-*.md ${Y}-handoff-*.md 2>/dev/null; } \
     | grep -v autohandoff | sort -u | while read f; do
         grep -q '^> *상태: *✅' "$f" && continue
         grep -q '^> *상태: *🔵' "$f" && m=🔵 || m="⚠️ 표시없음"
         d=$(echo "$f" | grep -oE '^[0-9]{4}-[0-9]{2}-[0-9]{2}')
         # 오래된 것은 «접는다» — 빼는 게 아니다(오래됐다고 끝난 게 아니다)
         # 🔴 날짜를 못 읽으면 NEW — 「모르면 안 접는다」. 빈 값은 어떤 날짜보다 «작아서»
         #    그냥 두면 전부 접힌다(연도를 2026 으로 박았다가 잡은 갭 — 해가 바뀌면 전멸).
         if [ -z "$d" ] || [[ ! "$d" < "$CUT" ]]; then g=NEW; else g=OLD; fi
         one=$(grep -A2 '^## 한 줄' "$f" | grep -v '^##\|^$\|^--' | head -1)
         echo "$g|$m|$f|$one"
       done | sort
   # NEW(최근 3일)만 보여주고, OLD 는 개수만 알린다
   ```

   #### 🔴 오래된 것은 접는다 (2026-08-13 신설)

   **왜**: 끝난 작업에 종결 표시(`✅`)를 안 찍으면 `🔵 진행` 인 채로 남아 **매번 후보로 올라온다.**
   운영 환경 실측 — 「진행 중」 **55건** 중 **24건(44%)이 3일 이상 손 안 댄 것**이었고
   거기에 **이미 끝난 작업이 섞여 있었다**(다른 세션이 이어받아 끝냈는데 앞 파일은 안 닫힘).
   그 상태로 55줄을 늘어놓으면 **어느 걸 이어야 하는지 알 수 없다.**

   출력에 이 한 줄을 더한다:
   ```
   📁 3일 이상 손 안 댄 것 M건 — "묵은 거" 라고 하시면 펼칩니다
   ```

   ⚠️ **접는 것이지 빼는 것이 아니다** — 3일 미뤄뒀지만 살아있는 작업이 실제로 있다.
   🔑 **닫는 일은 `/jedi-save` 가 한다** — 여기는 읽기만 하고 파일을 고치지 않는다.

   #### ✅ 「이미 끝난 것」을 기계가 골라 준다 (2026-08-19 신설)

   위 「접기」는 **얼마나 오래됐나**로만 가른다. 그런데 오래된 것 ≠ 끝난 것이고, **어제 끝난 것**도 있다.
   `/jedi-save` 가 핸드오프에 적어 둔 `> 완료조건:` 줄을 검사하면 그것이 갈린다.

   ```bash
   node plugins/jedi-core/skills/jedi-save/handoff-done-check.js --json
   ```

   출력에 이 한 줄을 더한다 (**0건이면 줄 자체를 쓰지 않는다**):
   ```
   ✅ 끝났을 수 있는 것 N건 · ⏳ 답 하나면 닫히는 것 M건 — "닫을 거" 라고 하시면 펼칩니다
   ```

   🔴 **`unknown`(검사 못 함)을 「끝남」에 넣지 말 것** — `gh` 미설치·네트워크 실패로 못 잰 것이다.
   「미충족」도 아니다. 셋을 갈라 세고, `unknown` 이 있으면 그 사실을 함께 말한다.

   🔴 **AI 가 임의로 닫지 말 것** — 이 도구는 **후보까지만** 낸다. 실제로 닫는 것(`✅ 종결` 표시)은
   사람이 *"그거 끝났어"* 라고 말했을 때 `/jedi-save` 가 한다.

   ⚠️ 옛 핸드오프에는 이 줄이 없다(`no_condition`) — **정상이다.** 그 작업을 이어받으면 그때 채워진다.

   #### 🪟 창을 여러 개 띄웠을 때 — 어느 창에서 하던 것인가 (2026-08-11 신설)

   창을 두세 개 띄워놓고 일하면, 위에서 고른 후보가 **내가 방금 하던 것인지 옆 창 것인지** 알 수 없다.
   잘못 고르면 옆 창에서 진행 중인 작업을 처음부터 다시 시작하게 된다.

   > 실측(2026-08-11, 팀 저널 30일): 한 사람이 **하루 최대 16건**을 적재한다. 하루에 트랙 여러 개가 오간다는 뜻이다.

   **「내 창의 직전」 판정 — 위에서부터. 아래로 갈수록 약하다**

   | 순위 | 무엇을 보나 | 왜 |
   |---|---|---|
   | 1 | **`/시작` 뒤에 붙어온 핸드오프 경로** | `/jedi-save` 결과가 그대로 붙은 것 = **같은 창의 연속** |
   | 2 | **말한 내용의 단서** ("카드", "블로그"…) | 지금 하려는 것 |
   | 3 | 지금 있는 폴더(cwd)와 맞는 트랙 | 같은 창은 보통 같은 폴더에서 일한다 |
   | 4 | 가장 최근 파일 | 🔴 **이것만으로는 근거가 못 된다** — 아래를 함께 볼 것 |

   **🚨 다른 사람이 지금 잡고 있나 (후보를 보여주기 「전에」)**

   팀 저널에서 오늘 적재된 것을 본다. ID는 하드코딩하지 말고 얻는다:

   ```bash
   node "$HOME/.claude/plugins/marketplaces/zulgap-team-pack/teampack-config.js" notion.team_journal_ds
   ```

   얻은 ID로 오늘 행의 **`작성자`·`세션`** 을 조회해, 후보와 겹치는 것이 있으면 **1순위에서 내리고 경고를 붙인다**.

   - 작성자가 **나와 다르면** → 다른 사람이 하는 중일 수 있다
   - 작성자가 **나인데 시각이 다르면** → 내 다른 창일 수 있다

   **출력 (순서 엄수 — 후보를 길게 나열하지 말 것)**

   ```
   🚨 다른 분이 진행 중으로 보입니다 (건드리지 마세요)
      · <트랙> — <작성자>님이 N분 전 저장

   🪟 이 창의 직전 — <제목>
      → 핸드오프: <경로>  |  남은 것: <## 한 줄>
      이어서 하시겠습니까?

      (그 외 진행 중 N건 — "목록" 이라고 하시면 펼칩니다)
   ```

   - 🚨 블록은 **해당 없으면 통째로 생략**한다(매번 뜨면 신호가 죽는다). 단 **확인은 반드시 하고** 생략
   - 4순위(시각)로 내려갔으면 **"다른 창 것일 수 있습니다"를 반드시 붙인다** — 확신이 없을 때 확신 있는 척하는 것이 이 상황 최대의 사고 원인이다
   - 잡힌 트랙을 **빼지 말고 경고와 함께 보여준다** — 그 창을 이미 닫았을 수도 있다. 판단은 사람이 한다

   **고르는 순서**:
   0. **위 🪟 「내 창의 직전」 판정을 먼저 적용한다** — 창을 하나만 쓰고 있으면 건너뛰어도 된다
   1. **말한 내용에 단서가 있으면 그것부터** — "카드", "블로그", "보고서" 같은 말이 나왔으면 파일명·`## 한 줄` 로 맞춰 **1~2개로 좁힌다**. 보통 여기서 끝난다
   2. 단서가 없으면 **후보를 `## 한 줄` 과 함께 보여주고 고르게 한다**. 🔴 **아무거나 하나 골라 시작하지 말 것** — 가장 최근 파일이 이어가려던 그 작업이라는 보장이 없다
   3. `⚠️ 표시없음` 은 **옛 파일**(이 규칙 이전에 쓴 것). 후보로는 쓰되, 그 작업을 이어받았으면 이번 `/jedi-save` 에서 `상태:` 줄을 채워 넣는다

   **함정**:
   - 🔴 **`export LC_ALL=C` 를 빼면 1순위 필터가 조용히 꺼진다** — 🔵 같은 이모지는 4바이트라
     UTF-8 로케일에서 `grep` 이 **한 건도 못 찾는다**. 실측(2026-08-10, 파일 749개):

     | 로케일 | 🔵 찾음 | ✅ 찾음 |
     |---|---|---|
     | 설정 없음 | 18 | 18 |
     | `ko_KR.UTF-8` · `en_US.UTF-8` · `C.UTF-8` | **0** | 18 |
     | 위 셋 + `LC_ALL=C` | **18** | 18 |

     ✅(3바이트)는 어디서든 되고 🔵(4바이트)만 안 된다. **에러가 아니라 「0건」** 이라 목록은
     그럴듯하게 나오고(2일치 폴백만 돌아간다) **2일 넘게 미뤄둔 진행 중 작업이 통째로 사라진다.**
   - ⚠️ **후보가 여러 개인 것 자체는 정상** — 실제로 여러 작업이 진행 중일 수 있다. 문제는 개수가 아니라 **뭔지 모르는 것**이라, `## 한 줄` 을 꼭 같이 보여준다
   - ⚠️ **오래됐다고 끝난 게 아니다** — 며칠 미뤄둔 살아있는 작업이 있다. 날짜로 자르는 건 옛 파일용 임시방편이고, 진짜 판정은 `상태:` 줄이다

> 🔎 **먼저 판정**: "전에 뭐 했지 / 지난 작업 찾아줘 / 예전에 어떻게 했지" 처럼 **과거 이력**을 물으면 → 아래 1~3 대신 **§ 과거 회상**으로 바로 간다 (되묻지 말고 실행).

1. **회사 허브 fetch**
   - 위 § 회사 허브 명령으로 **페이지 ID를 먼저 얻는다** (하드코딩 금지).
   - Notion MCP `notion-fetch` 호출: `id = <위에서 얻은 ID>`
   - 실패 시: 링크만 제시하고 보고 (노션 권한이 없으면 관리자에게 해당 페이지 공유를 요청).

2. **현황 파악**
   - 제품/섹션 + 각 제품의 **진행 현황 스냅샷**(✅ 배포 완료 / ⬜ 구현 예정) 추출.

3. **요약 출력** — 아래 형식으로 제시:

   ```
   🧭 마스터 허브 로드 완료

   📦 제품 현황
   - {제품명}: {한 줄 현황}
   - ...

   📌 오늘 후보
   1. {제품} — {다음 작업}
   2. ...

   어느 것부터 진행할까요?
   ```

## 과거 회상 (지난 작업 찾기)

"전에 이거 어떻게 했지?", "지난주에 뭐 했지?", "○○ 관련 예전 작업/글 찾아줘" 처럼 **과거 작업·결정·산출물**을 물으면 → 아래를 **바로 실행**한다 (되묻지 말 것). 읽기 전용 + 본인 토큰 기준 자동 격리라 안전하다.

### 2소스 병렬 (한 곳만 보지 말 것)

| 소스 | 도구 | 무엇이 들었나 |
|---|---|---|
| ① 지시문 + 세션 저널 | `recall_prompts({ query, limit: 8, source: "all" })` | 과거 지시 + 팀 세션 저널 요약 (벡터 검색) |
| ② 산출물 | `notion-search` | 실제 결과물(블로그·보고서·기획서 등). 키워드 검색 |

- 두 소스를 **한 메시지에서 병렬 호출** (순차 금지 — 느림).
- 🔴 **노션은 키워드 검색 → 쿼리 2~3개 변주 필수**: ① 이름만 ② 이름+카테고리 ③ 카테고리만. 1회 검색 결과로 "없습니다" 단정 금지.
- `recall_prompts`는 실시간이 아니다 (과거 세션 전용) — 방금 한 발화는 안 잡힌다.
- jedi 토큰이 없으면 recall은 자동 skip → notion-search만으로 답하고, 토큰 발급을 관리자에게 요청.
- 결과는 **어느 소스에서 나왔는지 출처를 붙여** 답한다.

## 함정

- 마스터 허브는 **링크 허브** — 내용을 여기서 복제·수정하지 말 것 (정본은 각 하위 페이지에서만).
- 이 스킬은 **읽기 전용** — 스냅샷을 임의로 고치지 않는다.
- 노션 페이지가 안 열리면 = 권한 문제 → 관리자에게 마스터 허브 공유 요청.
