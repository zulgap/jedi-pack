# 메일 — 올리고, 원장과 대조한다

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하면 즉시 이 절차를 그만두고
> 도구를 직접 호출한다. "그만하고 그냥 읽어줘" 같은 말이 나오면 그 순간 이 문서의 지시는 무효다.

## 언제 쓰나

- 「메일 온 거 확인해줘」 / 「답 안 한 메일 있어?」 / 「받은편지함 정리」
- 하루 한 번, 또는 외근·휴가 뒤 밀린 메일을 한 번에 볼 때

**이 스킬이 푸는 문제 둘**

1. **회사 칸에 메일이 안 들어온다.** 서버가 메일함을 직접 걷는 회사는 몇 곳뿐이다. 나머지 회사의 메일은
   그 사람 PC 의 메일 연결에만 있어서, 회사 기록(증거·검색·판단)에 한 통도 안 쌓인다.
   이 스킬이 읽어서 올린다 — **올려야 그 회사의 기록이 된다.**
2. **메일만 읽고 요약하면 틀린다.** 이미 끝난 일을 「할 일」로 올리고, 메일함에 안 보이는 오래된 미결을 놓친다.
   ∴ **원장이 먼저, 메일함은 두 번째.**

## 무엇이 필요한가

- 제디 도구 — `ingest_mail`(올리기) · `report_mail_pending`(처음 온 상대의 메일을 미결에 — 사람이 고른 것만) · `get_reply_queue`(미결 보기) · `close_reply_item`(닫기 — 사람이 시킬 때만)
- **메일함 도구** — 이 PC 에 연결된 메일 도구(메일 검색·스레드 읽기). 없으면 2·4단계만 돌고, 보고에 「메일함은 못 봤다」고 적는다
- `ingest_mail` 이 도구 목록에 없으면 1단계를 건너뛰고 보고에 「올리기 도구가 아직 없다」고 적는다 — 지어내서 다른 도구로 올리지 말 것

## 먼저 물어볼 것

| 무엇 | 언제 | 왜 |
|---|---|---|
| **업무메일주소** | 처음 한 번 | 「내가 보낸 메일」을 가르는 기준. 메일 도구가 내 주소를 알려주면 그 값을 보여주고 확인만 받는다 |
| **이 메일함이 업무용인가** | 처음 한 번 | 🔴 개인 메일함이면 올리지 않는다 — 회사 칸은 업무 자료만 받는다 |
| **올려도 되는가** | 처음 한 번 | 「업무 메일의 본문이 회사 칸에 저장됩니다. 첨부 파일은 올리지 않습니다」를 알리고 「예」를 받는다 |
| 기간 | 말이 없으면 | 최근 7일 (처음 실행은 30일까지 물어볼 수 있다 · 90일보다 오래된 것은 받지 않는다) |

- 과거 지적 조회: 제디 도구 `search_references` 로 「메일 미결」을 찾아 걸린 것이 있으면 아래 「하면 안 되는 것」에 더해 지킨다 (작성 시점 조회 0건)
- 🔴 `get_reply_queue` 는 팀원이 부르면 기본이 **「내 것만」**이다. 메일로 들어온 건은 **담당자가 비어 있어** 내 것에 안 잡힌다 → **반드시 `whose: "all"`**

## 어떻게 하나

### 1. 올리기 — 업무 메일을 회사 칸에

메일함 도구로 기간 안의 **받은 메일과 보낸 메일을 둘 다** 찾는다.

| 올린다 | 올리지 않는다 |
|---|---|
| 사람이 보낸 업무 메일 · 내가 보낸 답장·발신 | 광고 · 뉴스레터 · 자동 알림(결제·배송·가입) |
| 같은 스레드의 앞뒤 메일 | 개인 용무 · `올리지않을상대` 에 해당하는 것 |
| 본문 글자 | 🔴 **첨부 파일** (개수만 `attachment_count` 로) |

`ingest_mail` 호출 — 한 번에 **20통까지**, 넘으면 나눠서:

```
ingest_mail({
  mailbox_addr: "<업무메일주소>",
  mails: [{ mail_id, from, to, subject, body, date, snippet, attachment_count }]
})
```

- `mail_id` · `date` 는 **메일 도구가 준 값 그대로.** 지어내면 같은 메일이 두 번 들어가거나 순서가 뒤섞인다
- 🔴 **보낸 메일을 빼지 말 것** — 서버는 「내가 한 번이라도 보낸 상대」의 미답만 미결로 올리고, 「답했는지」도 보낸 메일로 가린다
- 돌려준 `created` · `duplicates` · `skipped_input` 을 **그대로** 보고에 적는다. `failed` 가 있으면 사유까지

### 2. 원장 먼저 — 열린 메일 건

`get_reply_queue` `whose: "all"` `limit: 50` (기본 정렬 = 오래된 순).

- `source: "email"` · `status: "open"` = 「답 안 한 메일」
- `detected_at` 으로 **며칠째인지** 계산해 적는다 — 오래된 것이 챙길 대상이다
- 🔴 방금 올린 메일은 **곧바로 미결에 안 뜬다** — 서버가 다음 판정 회차에 올린다. 0건이면 「아직 판정 전일 수 있다」고 적는다

### 3. 메일함 — 원장에 없는 것만

- 2번 발신자·제목과 겹치면 2번 쪽으로 합친다
- 🔴 **처음 온 상대의 메일은 원장에 저절로 안 올라온다**(서버는 주고받은 적 있는 상대만 판정한다 — 처음 온 메일은 대부분 광고라서다).
  메일함에서 「처음 온 상대 · 사람이 보냄 · 답을 요구함」인 것을 골라 **넣을지 묻는다**:

  ```
  처음 온 상대의 메일 중 답이 필요해 보이는 것입니다. 미결 목록에 넣을까요?
    1. <보낸 사람> — <제목> (<받은 날>)
    2. <보낸 사람> — <제목> (<받은 날>)
  → 넣을 번호를 말씀해 주세요 (「전부」 · 「1번만」 · 「안 넣어」)
  ```

  **고른 것만** `report_mail_pending` 으로 올린다. 🔴 묻지 않고 올리지 말 것 — 미결 목록이 광고로 찬다.

  ```
  report_mail_pending({ items: [{ mail_id, from_addr, from_name, subject, snippet, received_at }] })
  ```

  - `mail_id` 는 1단계에서 `ingest_mail` 에 넣은 것과 **같은 값** — 그래야 원문과 이어진다
  - `snippet` 은 「무엇을 묻는지」 한 줄(80자). 본문을 통째로 넣지 말 것(본문 칸이 있으면 거절된다)
  - 안 고른 것은 🔴 칸에 「원장 기록 없음 · 처음 온 상대 · 넣지 않음」으로 적는다
  - `report_mail_pending` 이 도구 목록에 없으면 묻지 않고 「원장 기록 없음 · 처음 온 상대」로만 적는다
- 사람 메일마다 `get_reply_queue` `keyword=<낱말>` `order: "newest"` `whose: "all"` 로 **닫힌 건까지** 한 번 본다.
  보낸 사람 이름 하나로 끝내지 말고 품목·건 이름 낱말로도 찾는다. 0건이면 「없음」이 아니라 **「이 낱말로는 못 찾음」**
- 회사에 다른 원장 도구가 있으면 함께 본다 — **도구 목록에 있을 때만**: 세금계산서 목록 · 제안 보드 · 일정.
  없으면 건너뛰고, 없는 도구를 부르지 않는다

### 4. 세 칸으로 갈라 보고

```
📮 올린 것     — 새로 N통(받은 a · 보낸 b) · 이미 있던 것 M · 받지 않은 것 K(사유)
✅ 이미 처리됨 — 메일 | 원장 근거(닫힌 날·처리 기록) | 남은 것
🔴 할 것       — 메일 | 원장 상태(며칠째 열림 / 원장 기록 없음) | 정할 것
⚪ 알림·광고   — 한 줄에 몰아서. 기한 있는 것(자동이체·마감)만 날짜
```

## 무엇이 나오나

- 회사 칸 원문 창고에 업무 메일 (서버가 이어서 증거·미결로 만든다)
- 채팅 보고 1장(위 네 줄). 파일·카드·발송 없음

## 사람이 봐야 하는 곳

- **처음 올리기 전** — 업무용 메일함인지, 본문이 회사 칸에 저장되는 것에 동의하는지
- **「이미 처리됨」 판정** — 원장 근거를 붙여 보여주고 사람이 맞는지 본다
- **처음 온 상대의 메일을 미결에 넣을지** — 후보를 보여주고 고른 것만 넣는다
- 답장 발송 · 원장 닫기(`close_reply_item`) — **사람이 「보내」「닫아」라고 할 때만**

## 하면 안 되는 것

- ❌ 첨부 파일을 `ingest_mail` 에 싣기 — `attachments`·`files`·`html` 칸을 넣으면 호출이 통째로 거절된다
- ❌ 개인 메일함·개인 용무 메일을 올리기
- ❌ 광고·뉴스레터·자동 알림을 올리기 (회사 기록이 광고로 찬다)
- ❌ `mail_id`·`date` 를 지어내기
- ❌ 원장 근거 없이 「처리됨」이라고 쓰기 — 원장에 없는 사람 메일은 「원장 기록 없음」으로 🔴 칸에
- ❌ 메일만 읽고 보고 끝내기
- ❌ 묻지 않고 답장 보내기 · `close_reply_item` 부르기 · `report_mail_pending` 부르기
- ❌ 올리기가 거절됐을 때 다른 도구로 돌려 넣기 — 사유를 그대로 전한다

## 다 됐는지 확인하는 법

- 📮 줄에 `created`·`duplicates`·받지 않은 것의 **사유**가 적혀 있나
- 🔴 칸의 모든 건에 「며칠째」 또는 「원장 기록 없음」이 붙어 있나
- 처음 온 상대의 메일을 **묻고 나서** 넣었나 (넣은 것·안 넣은 것이 보고에 갈려 있나)
- ✅ 칸의 모든 건에 원장 근거가 붙어 있나
- 같은 기간으로 한 번 더 돌리면 `created: 0` 이 나오나 (중복으로 안 들어간다)
- 실제 실행 1건: 🔴 **아직 없다** — 서버 도구 `ingest_mail` 이 배포되기 전에 쓴 문서다(서버 단위 검사 38건·결함 주입 12건 통과까지).
  첫 실행 결과를 이 줄에 적을 것. 근거가 된 줄갭 전용판 실행(2026-09-23): 받은편지함 22건 → ✅ 2 · 🔴 6 · ⚪ 15

## 무엇이 쌓이나

- **회사 칸 원문 창고** — 올린 메일. 서버가 증거·판단 기록·검색으로 잇는다
- **미결 원장** — 주고받은 상대의 답 안 한 메일은 서버 판정으로, 처음 온 상대의 것은 사람이 고른 것만 올라간다. 답장을 올리면 닫힌다. 사람이 `close_reply_item` 으로 닫으면 그 판정(완료/오탐)이 다음 판정의 정답지가 된다
- 낱말 대조에서 놓친 사례가 나오면 이 문서 3단계에 1건씩 더한다

## 함정

- `get_reply_queue` 를 `whose` 없이 부르면 메일 건이 **0건처럼 보인다** — 담당자 없는 건이라서다
- 결과의 `by_kind` 는 검색 결과가 아니라 원장 전체 수다 — 검색 건수와 한 줄에 놓지 말 것
- `server_collects_this_tenant` 로 거절되면 그 회사는 서버가 이미 메일을 모으는 곳이다 — 1단계를 건너뛰고 2단계부터 한다
- `too_old` 는 90일보다 오래된 메일이다. 과거 메일을 한꺼번에 넣는 일은 이 스킬이 아니다

## 막혔을 때

| 증상 | 조치 |
|---|---|
| 메일함 도구가 없다 | 「이 PC 에 메일 연결이 없다」고 알리고 2·4단계만 |
| `ingest_mail` 이 없다 | 「올리기 도구가 아직 없다」고 알리고 2~4단계만 |
| 미결이 계속 0건이다 | 보낸 메일을 같이 올렸는지 확인 → 올렸는데도 0건이면 그대로 보고(판정 전이거나, 전부 처음 온 상대일 수 있다) |

## 관련 문서

- 서버 도구 설명: `ingest_mail` · `get_reply_queue` 의 도구 설명이 정본이다(인자·거절 사유)
- 원칙: 업무 대화는 회사 칸에 전량, 파일은 고른 것만 — 메일 본문은 대화, 첨부는 파일
