> `jedi-youtube-channel/PROVENANCE.md` § 섹션 지도에 있다. 여기는 **발표자료 절**의 근거만 적는다.

## 🎬 발표자료 절 — 어디서 나왔나 (2026-08-16 신설)

한 고객사 채널의 2부작(슬라이드 **68장**)을 실제로 만들면서 얻은 것을 옮겼다.
**사후 정당화가 아니라 그날 실패한 것을 고친 기록**이다.

| 그날 벌어진 일 | → 이 스킬의 무엇이 됐나 |
|---|---|
| 슬라이드 **6장이 세이프존을 50px 침범**했는데 육안으로는 전부 멀쩡해 보였다 | `scripts/check-safezone.js` — 눈이 아니라 렌더 측정으로 판정 |
| 브랜드 색이 아닌 색(노랑)이 **133곳**에 퍼진 뒤 사람 지적으로 발각됐다 | 팔레트를 채널 정본 `palette`에서 읽는 규약 · 템플릿은 회색조 기본값 |
| 페이지 번호가 우하단이라 PiP와 정면 충돌했다 | `deck.html` 의 `#idx` 를 좌하단 고정 |
| 대사를 어디에 둘지 정해지지 않아 슬라이드 본문과 섞였다 | `data-script` / `data-note` 분리 — 프롬프터가 note 를 낭독에서 뺀다 |
| 촬영 준비물(측정·캡처)이 대본 어디에도 없어 촬영 직전에 드러났다 | `templates/cue-sheet.md` 의 「촬영 전 준비」 절 |

### 세이프존 판정선의 유래

PiP가 우하단을 **상시** 점유하는 촬영 컨셉에서 나온다. 값 자체(PiP 크기·마진·세이프존 높이)는
**채널 정본 `production`** 에 있고 이 스킬은 그것을 읽기만 한다 — 회사마다 다른 값이라
공용 팩에 두면 안 되기 때문이다(패키징 규약 §1 4등급 B).

측정 방식은 `getBoundingClientRect` 원본값 비교다. **LLM 0** — 「대충 괜찮아 보임」이 끼면
이 게이트의 값어치가 통째로 사라진다.

## 이식성 (패키징 규약 §1 실행 이식성)

`check-safezone.js` 는 Chrome 실행 파일을 **후보 배열**에서 찾는다 — Playwright 캐시(버전 폴더 가변),
Windows/macOS/Linux 표준 설치 경로, Edge(Chromium 계열), 그리고 `CHROME_PATH` 환경변수.
하나도 없으면 **조용히 넘어가지 않고** 확인한 경로를 전부 보여주며 실패한다.

임시 검사 파일은 tmpdir 이 아니라 **원본 옆**에 만든다 — 슬라이드가 `_capture/` 같은 상대경로 자산을
참조하므로, 옮기면 그 장들이 빈 채로 측정돼 「통과」가 나온다.

### 지시문 판정에 «리터럴 목록」을 쓰지 않은 이유

`하십시오` 류를 리터럴로 잡으면 *"여러분 ~하십시오"* 같은 **정당한 대사**를 잡는다. 오탐이 나면
사람이 경고를 무시하게 되고, 그러면 검사가 없는 것과 같아진다.

대신 **`data-note` 와 화면 텍스트의 공통 문장**(12자 이상)을 본다. 연출 지시는 이미 `data-note` 에
선언돼 있으므로, 같은 문장이 화면에도 있으면 **샌 것이 확정**이다. 오탐이 원리적으로 0이다.

⚠️ 한계 — `data-note` 에 없던 지시문이 화면에만 있으면 못 잡는다. 그건 사람이 본다.

### 이미지 미로드를 «별도로, 더 시끄럽게» 알리는 이유

안 실린 이미지는 높이 0으로 재므로 **세이프존이 「통과」로 나온다.** 그 통과는 거짓이고,
사람은 통과를 봤으니 다시 재지 않는다. 그래서 침범·잘림과 **분리해** 「이 측정은 틀렸다」고 알린다.

실측: 자리표시자일 때 `bottom 715` 통과 → 진짜 캡처를 넣자 `735`, **15px 침범**.

### 검증 방법 (대조군 2벌)

정상본이 통과하는 것만으로는 «검사가 도는지» 모른다. **결함을 일부러 되살려** 잡히는지 봤다.

```
대조군 A  오늘 고친 1편        → exit 0 (전부 통과)
대조군 B  결함 3종 주입한 사본  → exit 1 (34장 지시문 · 30장 __% · 37장 미로드 전부 검출)
```

**녹화본 자체가 못 쓸 물건이었다** — 재는 자리가 슬라이드에만 있었기 때문이다.

|---|---|

| 음량이 **-27.1 LUFS** 로 녹음됐다(유튜브 -14 대비 13dB 부족). 유튜브는 큰 소리는 줄여주지만 **작은 소리는 키워주지 않는다** | 같은 스크립트의 `ebur128` 라우드니스·트루피크 판정 · 큐시트 「마이크 음량」 |

### 왜 「촬영 전」과 「촬영 후」를 한 스크립트가 재나

원인(설정)과 결과(파일)가 **어긋날 수 있기 때문**이다. 설정만 재면 OBS 를 켜 둔 채 잰 값이 낡았을 수
있고, 파일만 재면 «왜» 그렇게 나왔는지 모른다. 둘을 나란히 찍으면 `출력 1280×720` 과
`파일 1280×720` 이 함께 보여 원인이 바로 드러난다.

🔴 **OBS 실행 중 경고를 넣은 이유** — OBS 는 «종료할 때» 메모리 값으로 `basic.ini` 를 덮어쓴다.
설정을 바꾸고 켜 둔 채 재면 바꾸기 «전» 값이 읽힌다. 그 판정은 믿을 수 없으므로 조용히 통과시키지 않는다.

### 안 잰 것을 통과로 적지 않는다

ffmpeg 가 없으면 음량을 못 잰다. 그때 이 스크립트는 «통과» 가 아니라 **「못 쟀음」** 으로 적는다.
안 잰 것이 통과로 적히는 순간 게이트는 거짓말이 되고, 다음 사람은 그 거짓말을 믿고 찍는다.
(편집기가 번들로 가진 ffmpeg 를 먼저 찾으므로 대개 추가 설치는 필요 없다.)

### 검증 방법

만든 날 **실제 사고 파일과 실제 OBS 설정**으로 돌려 **실패 6건을 재현**했다 —
출력 해상도 · 녹화 품질 · 비트레이트(설정) · 해상도 · 비트레이트(파일) · 음량.
피크(-5.1dB)는 통과했고, 이는 *「작게 녹음됐을 뿐 깨지지는 않았다」* 는 판정과 일치한다.

⚠️ 만드는 도중 두 번 «조용한 통과» 가 나왔고 둘 다 실측으로 잡았다 — ① `--obs <파일>` 에서 파일명이
옵션 값으로 먹혀 파일 검사가 통째로 빠졌다 ② ffmpeg 가 측정값을 stderr 로 내는데 stdout 만 읽어
음량이 「못 쟀음」이 됐다. **둘 다 화면상으로는 정상처럼 보였다.**

### 🔑 오탐을 세 번 걷어냈다 — 정확도만큼 중요하다
