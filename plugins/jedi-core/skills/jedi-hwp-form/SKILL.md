# 한글 양식 채우기

> 🔓 **이 문서는 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하거나
> "그만하고 그냥 해줘"라고 하면 그 순간 이 절차는 무효다.

기존 `.hwp`/`.hwpx` 양식의 빈칸을 채워 제출 가능한 완성본을 만든다.
**백지에서 새 문서를 만드는 일은 이 스킬의 범위가 아니다** — 서식 정의를 통째로
지어내야 해서 검증된 처방이 없다.

## 이 일이 어려운 이유 (먼저 읽을 것)

한글 파일은 세 가지가 동시에 발목을 잡는다.

1. **`.hwp` 는 쓰기가 사실상 막혀 있다.** 파이썬으로 `.hwp` 를 직접 고쳐 쓰는 길이
   있어 보이지만, 그렇게 만든 파일을 **한글이 열지 못한다**(양식 2종 2/2 거부 실측).
   → **모든 편집은 `.hwpx` 로 하고, `.hwp` 는 양 끝에서 변환만 한다.**
2. **문자열 치환 한 줄로는 안 된다.** 아래 함정 12종이 전부 안 걸러진다.
3. **틀려도 조용하다.** XML 이 깨지면 한글은 예외도 경고도 없이 **빈 문서를 연다.**
   그래서 판정은 언제나 결과 PDF 로 한다.

## 준비물

| 무엇 | 언제 필요 | 없으면 |
|---|---|---|
| 한컴오피스 (Windows) | `.hwp` ↔ `.hwpx` 변환, PDF 뽑기 | `.hwpx` 로 주고받으면 **불필요** |
| `pymupdf` | 검수 | `pip install pymupdf` |
| `pywin32` | 변환 | `pip install pywin32` |
| `hwp-mcp` (MCP) | 양식 훑어보기 | 없어도 됨 (아래 1단계 대안 있음) |

시작 전에 **한컴 설치 여부를 먼저 확인**한다. 없는데 `.hwp` 를 받았다면 그 자리에서
알리고 멈춘다 — 중간까지 갔다가 변환에서 막히면 한 일이 버려진다.

**한글 창이 뜨거나 확인창이 나오는 것은 스크립트가 알아서 처리한다.** 보안 승인창은
첫 실행 때 자동 등록으로 없애고(HKCU, 권한 불필요), 「상위 버전에서 작성한 문서입니다」
같은 창은 감시해서 눌러준다. 등록 전에는 **파일 하나 여는 데 42.5초**가 걸렸다(등록 후 0.1초).

## 절차

### 1단계 — 양식을 훑는다 (추측 금지)

`.hwp` 로 받았다면 **읽기는 `hwp-mcp` 도구가 가장 빠르다**(한컴 없이 읽는다):
`read_hwp` 로 전체 구조, `read_hwp_tables` 로 표, `list_hwp_images` 로 그림.

채우려면 `.hwpx` 가 필요하므로 변환한 뒤 칸 주소를 뽑는다:

```bash
python scripts/hwpform.py to-hwpx "<양식.hwp>" "<작업.hwpx>"
python scripts/hwpform.py inspect "<작업.hwpx>"
```

출력에서 **세 가지**를 확보한다 — ① 칸 주소 `(row, col)` 와 현재 글자
② `[빈칸]` 표시된 칸 목록 ③ 본문에 쓸 글꼴 서식 번호(검정·12pt 등).

### 2단계 — 어느 칸에 무엇을 넣을지 사람과 확정한다

라벨과 값 칸은 **다른 칸**이다. `'휴 대 폰'` 이 (r2,c3) 이면 값은 대개 (r2,c5) 다.
표에서 라벨↔값 짝을 지어 사용자에게 보여주고 확정받는다.

🔴 **빈칸으로 두는 것도 결정이다.** 값을 모르는 칸은 지어내지 말고 물어본다.
사용자가 "비워두라"고 하면 그건 미기입이 아니라 확정이므로 그대로 둔다.

🔴 **글자가 보인다고 다 값은 아니다.** 한글 **메모**(주석)는 파일에 글자로 들어
있지만 인쇄되지 않는다 — 그 칸은 사실 빈 칸이다. 그런 칸의 글자를 갈아치우면
넣은 값이 안내문 서식(붉은색)으로 메모 안에 들어가 **결과물에서 사라진다.**

### 3단계 — 채운다

`hwpx_lib` 을 불러 쓰는 짧은 스크립트를 쓴다. 칸 상황마다 부를 함수가 다르다:

| 칸 상황 | 함수 |
|---|---|
| 완전히 빈 칸 | `set_cell(xml, r, c, 값)` |
| 라벨 뒤에 값을 붙임 (`'성명 :'` → `'성명 : 홍길동'`) | `replace_text(xml, 찾을글자, 바꿀글자)` |
| 글자가 여러 조각으로 갈려 치환이 0건 | `set_cell_whole` / `append_cell` / `replace_after` |
| 인쇄 안 되는 메모만 있는 칸 | `prepend_cell(xml, r, c, 값, 서식번호)` |
| 사진 자리 (누름틀 등 구조 복잡) | `set_cell_content` |

**치환은 반드시 건수를 확인한다.** `replace_text` 는 바뀐 건수를 함께 돌려준다.
기대와 다르면 **거기서 멈춘다** — 0건은 조각이 갈렸다는 뜻이고, 그냥 넘어가면
값이 안 들어간 채로 완성본이 만들어진다.

```python
xml, n = H.replace_text(xml, '성        명 :', '성        명 : 홍길동')
assert n == 1, '치환 %d건 — 조각이 갈렸는지 inspect 로 확인할 것' % n
```

🔴 **건수 검사가 「대상 0건」을 통과시키지 않게 한다.** 여러 곳을 고칠 때
`assert all(v == 1 for v in 결과.values())` 만 쓰면 **결과가 빈 dict 일 때 `all([])` 이 True** 라
한 곳도 안 고치고 조용히 지나간다(실측: 함정 ⑭ 로 0건이었는데 그대로 통과했다).
**키 집합까지** 대조할 것:

```python
assert set(고친것) == set(대상), '기대 %r — 실제 %r' % (대상, sorted(고친것))
```

### 그림 — **표 셀에 넣는다** (문단에 직접 붙이지 말 것)

문단에 붙인 그림은 **이미지의 픽셀 수**가 크기를 정한다. `<hp:sz>`·`<hp:orgSz>`·
이미지의 DPI 메타데이터 **셋 다 무시된다**(실측 3종). 그래서 110mm 로 보이게 하려면
416px 까지 줄여야 하고, 그 값은 **96dpi** 라 인쇄하면 거칠다.

**표 셀 안에 넣으면 셀 크기가 표시 크기를 정한다.** 원본 1025px 을 그대로 넣어도
110mm 로 잡혔다 — 같은 크기에 해상도만 96 → 237dpi.

```python
pic = H.pic_node(iid, w, h, w, h, 1, 'PARA', 'COLUMN', z=z, name=...)
tbl = H.pic_table([(pic, w, h)], tid)        # 1행 1열. 여러 개면 한 행에 나란히
xml = xml[:i] + tbl + xml[j:]                # 옛 그림 노드 자리에 끼운다
```

**예외 — 도장**: 「(서명/인)」 글자 **옆**에 찍혀야 하므로 표로 감싸면 나란히 놓을 수
없다. 도장은 그 문단의 run 뒤에 직접 붙인다(원본이 작아 화질 손실도 거의 없다).

그림을 **문단에** 붙여야 하는 경우에는 `px_for_mm` 으로 **넣기 전에 픽셀을 줄이고**,
`anchor_pic_first_para` 로 **앞쪽 문단**에 매단다.

저장 직전에 반드시:

```python
H.check_wellformed(section0=s0, hpf=hpf)     # 빼먹으면 한글이 빈 문서를 연다
H.save(작업hwpx, 결과hwpx, replaced={...}, add_files={...})
```

```bash
python scripts/hwpform.py to-hwp "<결과.hwpx>" "<완성본.hwp>" "<완성본.pdf>"
```

### 4단계 — 검수한다 (눈으로 보기 전에 숫자로)

```bash
python scripts/hwpform.py verify "<완성본.pdf>" --expect-pages <기대쪽수>
```

확인 항목: 쪽수 · 그림 크기와 위치(mm) · 종이 밖으로 넘친 줄 · 안 채운 자리 흔적.
같은 양식의 이전 완성본이 있으면 `--baseline "<기존.pdf>"` 로 대조한다.

**쪽수가 늘었으면 넘어가지 말 것.** 아래 함정 ⑦⑧⑮⑯ 중 하나다.

`verify` 가 **「안 채운 자리」**를 짚어도 그 자체가 결함은 아니다 — 사용자가 비워두기로
한 날짜·서명란이면 그게 정답이다(셀프체크 6). 채울 곳인지 **먼저 확인**한다.

마지막에 **한글로 열어 눈으로 확인**하도록 사용자에게 안내한다. 숫자 검수는
사람 확인을 대신하지 못한다.

### 안 열릴 때 — 원본을 같은 길로 한 번 통과시킨다

`to-hwp` 가 **「열기 False」** 를 내면 원인 후보는 둘이다 — ①변환 경로·도구 ②내 편집.
**아무것도 안 고친 작업본(`work.hwpx`)을 같은 명령으로 변환**해 보면 1회에 갈린다.

```bash
python scripts/hwpform.py to-hwp "<작업.hwpx>" "ctrl.hwp" "ctrl.pdf"   # 무편집 대조군
```

그게 정상으로 열리면 도구는 멀쩡하고 범인은 **내 편집**이며, 가장 흔한 것이 함정 ①이다.
이 한 번을 건너뛰면 도구·변환·환경을 의심하며 시간을 쓰게 된다.

🔴 **`check_wellformed` 통과는 무죄 증명이 아니다** — XML 이 유효해도 줄배치 값이
어긋나면 한글은 아무 말 없이 문서를 포기한다(함정 ①).

## 함정 16종 (전부 실측)

| # | 함정 | 증상 | 처방 |
|---|---|---|---|
| ① | 줄배치를 그대로 둠 | 긴 값이 **한 줄에 그려져 칸 밖으로 넘침**(179자 실측). 🔴 심하면 **한글이 파일을 아예 못 연다** — 45자→75자 한 곳에서 11쪽이 3쪽으로 열렸고, `check_wellformed` 는 **통과**했다(XML 은 멀쩡하다) | 값 바꾼 문단은 `clear_lineseg`. 단 **빈 문단은 건드리지 말 것**. 전체(`clear_lineseg_text_paras`)에 걸면 이미 맞춰둔 레이아웃까지 재계산되므로 **바꾼 문단만 표적으로** |
| ② | 서식 번호를 남의 파일에서 가져옴 | 글자가 커지고 줄간격이 벌어져 **쪽수가 늘어남** | 번호는 **채우는 그 양식**에서 고른다. `inspect` 가 목록을 준다 |
| ③ | 그림 크기를 지정값으로 믿음 | 15mm 를 줬는데 **40mm 로 그려짐** | 넣기 전에 픽셀을 줄인다 (`px_for_mm`) |
| ④ | 칸을 `<hp:tc>` 짝맞춤으로 셈 | 표 안에 표가 있으면 **마지막 칸을 통째로 놓침** | `cell_spans`(칸주소 기준) 사용 |
| ⑤ | 한 칸의 글자가 여러 조각 | 치환이 **0건**인데 그냥 지나감 | 건수 확인 후 `set_cell_whole`/`replace_after` |
| ⑥ | 인쇄 안 되는 메모를 값으로 착각 | 넣은 값이 **결과물에서 사라짐** | `prepend_cell` 로 본문에 따로 넣는다 |
| ⑦ | 그림을 **마지막 문단**에 매닮 | 내용은 다 1쪽인데 **빈 2쪽**이 생김 | `anchor_pic_first_para` |
| ⑧ | 종이 기준 좌표를 그대로 믿음 | 그림이 **여백만큼 밀림**(왼쪽 25mm·위 15mm) | PDF 로 재서 차이만큼 빼고 다시 넣는다 |
| ⑨ | 깨진 XML 을 그대로 저장 | 한글이 **아무 말 없이 빈 문서**를 엶 | 저장 전 `check_wellformed` |
| ⑩ | 그림을 **문단에 직접** 붙임 | 크기를 맞추려 픽셀을 줄여야 해 **96dpi 로 흐려짐** | **표 셀에 넣는다** — 셀 크기가 표시 크기를 정해 원본 해상도가 살아난다 (`pic_table`) |
| ⑪ | 표를 먼저 넣고 옛 그림을 지움 | 표 안 그림이 **같은 ID** 라 방금 넣은 걸 지움 | 옛 노드를 **먼저** 전부 걷어내고 그 자리에 표를 끼운다 |
| ⑫ | ①②③ 목록 줄에 설명을 덧붙임 | 그 줄만 두 줄로 넘어가 **둘째 줄이 왼쪽 끝에 붙어** 정렬이 깨짐 | 같은 목록에서 **가장 긴 줄의 폭**을 먼저 잰다. 그게 한계에 차 있으면 여유가 없다(실측: 한계 59 / 최장 줄 59 / 대상 줄 57 → 여유 **2**, 가장 짧은 후보조차 폭 10이라 불가). 설명은 **아래 문단으로 내린다** |
| ⑬ | 이탤릭·굵게를 **속성**으로 찾음 | `italic="1"` 로 훑으면 **0건**인데 PDF 는 분명히 기울어져 있다 | 한글은 **자식 요소**로 쓴다 — `<hh:italic/>` · `<hh:bold/>`. 속성인 것은 색(`textColor`)뿐이다. 양식 안내문이 이탤릭이면 그 칸에 넣은 값이 **통째로 기울어진다**(실측: 과업지시서 한 문서에서 41곳) |
| ⑭ | `H.HPF` 를 header.xml 로 착각 | 서식을 고쳤는데 **0건 변경**, 그런데 **에러도 경고도 없다** | `H.HPF` 는 `Contents/content.hpf`(패키지 매니페스트)다. **글자 서식은 `Contents/header.xml`** — 상수를 믿지 말고 경로를 직접 쓴다 |
| ⑮ | 쪽수를 글자·줄간격으로 줄이려 함 | 줄간격을 160→150% 로 낮췄는데 **표 높이가 0.0mm 변함** | 셀 높이는 `<hp:cellSz height>` **선언값 고정**이라, 내용이 그 안에 들어가는 한 아무리 줄여도 안 줄어든다. 쪽수는 **여백**으로 조정한다(실측: 상단 15→8mm + 하단 10→5mm 로 2쪽→1쪽) |
| ⑯ | 표가 쪽을 넘는데 `pageBreak="CELL"` | 셀 내용이 두 쪽에 **잘리고**(`AP서버(개발용)` → 앞쪽엔 「…자동」, 뒤쪽엔 「(개발용) 배포」), **병합된 라벨이 다음 쪽에서 사라진다** | 본표를 `pageBreak="TABLE"` 로 바꾼다(행 단위로 넘어감). 표 자체를 다음 쪽부터 시작시키려면 그 표를 담은 문단에 `<hp:p … pageBreak="1">` |

## 하지 말 것

- **`.hwp` 를 직접 고쳐 쓰기** — 한글이 그 파일을 못 연다(2/2 실측)
- **`assert all(...)` 하나로 건수 검사를 끝내기** — 대상이 비면 `all([])` 이 **True** 라 조용히 통과한다(함정 ⑭ 를 놓친 실제 경로)
- **`content.replace()` 로 XML 통째 치환** — 태그 속성까지 오염된다
- **`&` `<` 를 그대로 넣기** — 파일이 깨진다 (`hwpx_lib` 은 자동 처리)
- **원본 양식 덮어쓰기** — 항상 사본으로 작업한다. 양식이 깨지면 처음부터다
- **값을 지어내기** — 모르는 칸은 물어본다
- **쪽수 불일치를 넘기기** — 함정 ⑦⑧⑮⑯ 이 거의 확실하다

## 마치기 전 셀프체크

1. `inspect` 로 칸 주소를 **직접 확인**했는가? (라벨 칸과 값 칸을 헷갈리지 않았는가)
2. 모든 치환의 **건수**를 기대값과 대조했는가? 0건을 넘긴 곳은 없는가?
2-1. 그 검사가 **대상이 비어도 통과**하지는 않는가? (`all([])` 은 True — 키 집합까지 볼 것)
3. 저장 전에 `check_wellformed` 를 불렀는가?
4. `verify` 의 **쪽수**가 기대와 같은가? 다르면 원인을 찾았는가?
5. 그림 크기·위치를 mm 로 **재봤는가**? (지정값이 아니라 결과값)
5-1. 그림을 **표 셀**에 넣었는가? (도장 제외 — 문단 직접은 96dpi 로 흐려진다)
6. 사용자가 "비워두라"고 한 칸을 임의로 채우지 않았는가?
7. 사용자에게 **한글로 열어 확인**하도록 안내했는가?
8. 글자 서식을 손댔다면 `<hh:italic/>` 같은 **자식 요소**까지 봤는가? (속성만 훑으면 0건이 나온다)
9. 표가 쪽을 넘는 문서라면 **넘어간 쪽의 첫 행**을 실제로 봤는가? (병합 라벨이 사라진다)
