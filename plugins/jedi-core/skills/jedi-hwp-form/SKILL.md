# 한글 양식 채우기

> 🔓 **이 문서는 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하거나
> "그만하고 그냥 해줘"라고 하면 그 순간 이 절차는 무효다.

기존 `.hwp`/`.hwpx` 양식의 빈칸을 채워 제출 가능한 완성본을 만든다.
**백지에서 새 문서를 만드는 일은 이 스킬의 범위가 아니다** — 서식 정의를 통째로
지어내야 해서 검증된 처방이 없다.

## 이 일이 어려운 이유 (먼저 읽을 것)

한글 파일은 세 가지가 동시에 발목을 잡는다.

1. **`.hwp` 는 쓰기가 사실상 막혀 있다.** 파이썬으로 `.hwp` 를 직접 고쳐 쓰는 길이
   있어 보이지만, 그렇게 만든 파일을 **한글이 열지 못한다**(양식 2종 2/2 거부 실측).
   → **모든 편집은 `.hwpx` 로 하고, `.hwp` 는 양 끝에서 변환만 한다.**
2. **문자열 치환 한 줄로는 안 된다.** 아래 함정 12종이 전부 안 걸러진다.
3. **틀려도 조용하다.** XML 이 깨지면 한글은 예외도 경고도 없이 **빈 문서를 연다.**
   그래서 판정은 언제나 결과 PDF 로 한다.

## 준비물

| 무엇 | 언제 필요 | 없으면 |
|---|---|---|
| 한컴오피스 (Windows) | `.hwp` ↔ `.hwpx` 변환, PDF 뽑기 | `.hwpx` 로 주고받으면 **불필요** |
| `pymupdf` | 검수 | `pip install pymupdf` |
| `pywin32` | 변환 | `pip install pywin32` |
| `hwp-mcp` (MCP) | 양식 훑어보기 — 🔴 **읽기 도구만** | 없어도 됨 (아래 1단계 대안 있음) |
| `pillow` | `stamp` (도장 크기 맞추기) | `pip install pillow` |

🔴 **`hwp-mcp` 는 읽기에만 쓴다** — `read_hwp` · `read_hwp_text` · `read_hwp_tables` · `list_hwp_images` · `extract_hwp_images`.
쓰기 도구 `replace_hwp_text` · `fill_hwp_template` · `create_hwpx_document` 는 **쓰지 않는다** — XML 을 통째 문자열로
치환하고 `&` `<` 를 이스케이프하지 않아 파일이 깨지거나 태그 속성까지 바뀐다(함정 ⑨ 와 「하지 말 것」 의
`content.replace()` 와 같은 길). 글자 바꾸기는 `replace` 명령, 칸 채우기는 3단계 함수로 한다.
⚠️ `read_hwp` 는 가로로 합친 칸(colspan)의 글자를 비워서 보여준다 — 표가 비어 보여도 실제로는 들어 있다.

🔴 **한글 작업은 이 도구(`scripts/hwpform.py` + `hwpx_lib`) 하나로 한다.** 세션마다 임시 스크립트를
새로 짜서 한글을 직접 띄우지 말 것 — 10/22 한 세션에서 도구가 일곱 벌로 갈라져 보안 모듈 이름·확인창
처리·종료 방식이 서로 달랐고, 멈춤 5번 이상·서식 소실·파일 삭제가 났다(전부 사람이 먼저 발견).
없는 기능이 필요하면 임시 스크립트가 아니라 **이 도구에 명령을 더한다.**

시작 전에 **한컴 설치 여부를 먼저 확인**한다. 없는데 `.hwp` 를 받았다면 그 자리에서
알리고 멈춘다 — 중간까지 갔다가 변환에서 막히면 한 일이 버려진다.

**한글 창이 뜨거나 확인창이 나오는 것은 스크립트가 알아서 처리한다.** 보안 승인창은
첫 실행 때 자동 등록으로 없애고(HKCU, 권한 불필요), 「상위 버전에서 작성한 문서입니다」
같은 창은 감시해서 눌러준다. 등록 전에는 **파일 하나 여는 데 42.5초**가 걸렸다(등록 후 0.1초).

## 절차

### 1단계 — 양식을 훑는다 (추측 금지)

`.hwp` 로 받았다면 **읽기는 `hwp-mcp` 도구가 가장 빠르다**(한컴 없이 읽는다):
`read_hwp` 로 전체 구조, `read_hwp_tables` 로 표, `list_hwp_images` 로 그림.

채우려면 `.hwpx` 가 필요하므로 변환한 뒤 칸 주소를 뽑는다:

```bash
python scripts/hwpform.py to-hwpx "<양식.hwp>" "<작업.hwpx>"
python scripts/hwpform.py inspect "<작업.hwpx>"
```

출력에서 **세 가지**를 확보한다 — ① 칸 주소 `(row, col)` 와 현재 글자
② `[빈칸]` 표시된 칸 목록 ③ 본문에 쓸 글꼴 서식 번호(검정·12pt 등).

### 2단계 — 어느 칸에 무엇을 넣을지 사람과 확정한다

라벨과 값 칸은 **다른 칸**이다. `'휴 대 폰'` 이 (r2,c3) 이면 값은 대개 (r2,c5) 다.
표에서 라벨↔값 짝을 지어 사용자에게 보여주고 확정받는다.

🔴 **빈칸으로 두는 것도 결정이다.** 값을 모르는 칸은 지어내지 말고 물어본다.
사용자가 "비워두라"고 하면 그건 미기입이 아니라 확정이므로 그대로 둔다.

🔴 **글자가 보인다고 다 값은 아니다.** 한글 **메모**(주석)는 파일에 글자로 들어
있지만 인쇄되지 않는다 — 그 칸은 사실 빈 칸이다. 그런 칸의 글자를 갈아치우면
넣은 값이 안내문 서식(붉은색)으로 메모 안에 들어가 **결과물에서 사라진다.**

### 3단계 — 채운다

`hwpx_lib` 을 불러 쓰는 짧은 스크립트를 쓴다. 칸 상황마다 부를 함수가 다르다:

🔑 **칸 주소가 정해져 있고 값을 통째로 넣는 일이면 스크립트 없이 `fill` 명령**으로 한다(아래 표). 아래 함수는
메모 칸·조각 칸처럼 칸마다 다른 처방이 필요할 때만.

| 칸 상황 | 함수 |
|---|---|
| 완전히 빈 칸 | `set_cell(xml, r, c, 값)` |
| 라벨 뒤에 값을 붙임 (`'성명 :'` → `'성명 : 홍길동'`) | `replace_text(xml, 찾을글자, 바꿀글자)` |
| 글자가 여러 조각으로 갈려 치환이 0건 | `set_cell_whole` / `append_cell` / `replace_after` |
| 인쇄 안 되는 메모만 있는 칸 | `prepend_cell(xml, r, c, 값, 서식번호)` |
| 사진 자리 (누름틀 등 구조 복잡) | `set_cell_content` |

**치환은 반드시 건수를 확인한다.** `replace_text` 는 바뀐 건수를 함께 돌려준다.
기대와 다르면 **거기서 멈춘다** — 0건은 조각이 갈렸다는 뜻이고, 그냥 넘어가면
값이 안 들어간 채로 완성본이 만들어진다.

```python
xml, n = H.replace_text(xml, '성        명 :', '성        명 : 홍길동')
assert n == 1, '치환 %d건 — 조각이 갈렸는지 inspect 로 확인할 것' % n
```

🔴 **건수 검사가 「대상 0건」을 통과시키지 않게 한다.** 여러 곳을 고칠 때
`assert all(v == 1 for v in 결과.values())` 만 쓰면 **결과가 빈 dict 일 때 `all([])` 이 True** 라
한 곳도 안 고치고 조용히 지나간다(실측: 함정 ⑭ 로 0건이었는데 그대로 통과했다).
**키 집합까지** 대조할 것:

```python
assert set(고친것) == set(대상), '기대 %r — 실제 %r' % (대상, sorted(고친것))
```

### 자주 하는 편집은 명령 하나로 (열기 → 고치기 → 건수 대조 → PDF → 검수까지)

입력은 `.hwp`·`.hwpx` 둘 다 된다. **출력을 `.hwp` 로 주면 같은 이름 `.pdf` 를 뽑아 `verify` 까지 자동**으로
돈다(쪽수가 원본과 다르거나 넘친 줄이 있으면 실패로 끝난다). 출력이 `.hwpx` 면 한컴 없이 끝난다.
**원본을 덮어쓰는 이름은 거부한다.**

| 하고 싶은 일 | 명령 | 멈추는 경우 (저장 안 함) |
|---|---|---|
| 칸 주소로 값 넣기 (여러 줄 본문 포함) | `fill <입력> <출력> --cells 칸.json` (`{"행,열": "값", "5,0": "첫 줄
둘째 줄"}` · 표 안 표는 `"행,열@1"`) 또는 `--set "행,열=값"` · 날인 검사 `--min-images N` | 없는 칸 · **그림이 든 칸**(도장 칸 — 덮으면 날인이 사라진다) · PDF 에 넣은 글자가 안 보임 · 옛 값이 남음 |
| 글자 여러 개 바꾸기 (회사명·날짜·금액) | `replace <입력> <출력> --map 목록.txt` (줄마다 `찾을 => 바꿀`) 또는 `--set "찾을=>바꿀"` | 한 개라도 **0건** · JSON 에 준 기대 건수와 다름 · 서식 경계로 조각나 **옛 글자가 남음** |
| 날짜만 빨갛게 | `color-dates <입력> <출력>` (날짜 모양 전부) · 특정 날짜만은 `--only` (아래) · `--expect N` | `--only` 중 못 찾은 날짜 · 기대 곳 수와 다름 · 0곳 |
| 채운 안내 칸을 본문 글자로 (파란 기울임 → 검정) | `recolor <입력> <출력> --text "채운 글자|…"` (기본 검정 + 기울임 해제 · `--color` · `--keep-italic` · `--expect N`) — 그 글자의 서식을 복제해 색·기울임만 바꾼다 | 못 찾은 글자(서식 경계로 조각남) · 기대 곳 수와 다름 · 0곳 |
| 여백 바꾸기 (쪽수 맞추기) | `margin <입력> <출력> --top 8 --bottom 5` (mm 명시값) | 여백 이름 틀림 |
| 칸에 그림 여러 장 (증빙 캡처) | `pics <입력> <출력> --cell 11,0 --cols 2 --images a.jpg b.jpg [--captions "①…" "②…"]` | 칸 주소 없음 · 설명 수 ≠ 그림 수 · PDF 에 그림이 덜 나옴 |
| 「(인)」 위에 도장 | `stamp <입력> <출력.hwp> --after "(인)" --image 도장.png [--mm 15]` (여러 곳이면 `--occurrence N`/`--all`) · **한컴 필요** | 같은 도장이 이미 있음(`--replace` 로 다시) · 0.5mm 안으로 안 맞음 |
| 도장·그림 지우기 | `delete-pics <입력> <출력> --near "(인)" [--name 도장.png] [--expect N]` | 지울 그림 0개 · 기대 개수와 다름 |
| 쪽을 넘는 표 나누기 | `table-split <입력> <출력> --contains "편 구성" --rows 8` (또는 `--table N` · `--page-break`) | 세로로 합친 칸이 자르는 줄을 넘음 |
| 줄 늘리기 (조항·항목 추가) | `add-lines <입력> <출력> --after "검수 기준:" --file 줄.txt` (또는 `--lines "…" "…"`) — 그 문단 바로 뒤에 **같은 서식** 문단을 줄마다 | 기준 글자가 든 문단이 1개가 아님 · PDF 에 더한 줄이 안 보임 |
| 그림으로 된 표를 한글 표로 | `text-table <입력> <출력> --pic image2 --rows 표.json --widths 30,70 --label-like "4,2" --value-like "0,2"` (`{"head": [..], "rows": [[..]]}`) — 그림 자리·폭 그대로, 칸 모양은 양식 안 진짜 칸에서 빌린다 | 그 그림이 1개가 아님 · 빌릴 칸 없음 · PDF 에 칸 글자가 안 보임 |
| 표 줄 지우기 | `delete-rows <입력> <출력.hwp> --table 3 --rows 8` (줄 번호 0부터 · 머리 줄 = 0 · `3-5` · `2,4`) · 확인 글자 `--must-contain "글자"` | 없는 표 · 범위 밖 줄 · 줄 전부(→ `delete-table`) · 합친 칸이 지울 줄과 남길 줄에 걸침 · 확인 글자 없음 · **쪽수·글자를 못 잼** |
| 표 통째 지우기 | `delete-table <입력> <출력.hwp> --table 4 [--caption "표 제목"]` (또는 `--contains "글자"`) | 없는 표 · `--contains` 가 서로 다른 표 여럿에 걸림 · 제목 문단이 정확히 1개가 아님 · **쪽수·글자를 못 잼** |

- `fill` 은 칸 내용을 **통째로** 바꾼다. 줄바꿈(`
`·`
` 같게)마다 문단 하나 — 문단 머리·글자 서식은 그 칸에서
  «글자가 든 첫 문단» 것을 그대로 쓴다. 한컴으로 칸을 지우고 넣던 옛 방식은 커서가 빈 문단 서식(12pt·다른 글꼴)을
  물려받아 **사람이 만든 원본(11pt)과 다른 글자로** 나갔다(10/23 멘토링 결과보고서 실측 — 내용은 같아 아무도 몰랐다).
  옛 서류를 틀로 쓰면 옛 칸 글자 중 새 값에 없는 것을 `verify` 가 «남았나»로 본다(함정 ㉑).
- `replace` 는 서식을 그대로 두고 **바뀐 문단의 줄배치만** 비운다(함정 ①). 한컴 「모두 바꾸기」 는 쓰지 않는다 —
  바꾼 자리의 빨간 날짜 같은 글자 서식이 사라졌다(10/22 실측).
- `color-dates` 는 **그 글자의 서식을 복제해 색만** 바꾼다 — 양식에 있는 아무 빨간 서식을 쓰면 크기가 달라진다.
  다시 돌려도 이미 빨간 곳은 건드리지 않는다. 특정 날짜만 칠하려면:

  ```bash
  python scripts/hwpform.py color-dates "<입력>" "<출력.hwp>" --only "2026.10.21|2026년 10월 22일"
  ```
- 조각나서 멈추면 `inspect` 로 그 칸을 찾아 아래 3단계 표의 `set_cell_whole` 로 넣는다.
- `pics` 는 그 칸 내용을 **통째로** 그림 표로 바꾼다(옛 그림을 먼저 걷어내 함정 ⑪ 이 안 난다). 그림은 원본
  해상도 그대로이고 칸 폭에 맞춰진다(함정 ⑩).
- `stamp` 는 PDF 로 「(인)」 자리를 재서 도장을 얹고, **다시 PDF 로 재서 0.5mm 안인지 확인**한다(함정 ⑧ 을 사람 대신
  고친다). 도장은 그 문단의 글자묶음 뒤에 붙는 «글 앞» 그림이라 글을 밀지 않는다.
- `delete-pics` 는 **그 글자가 든 문단의 그림만** 지운다 — 「몇 번째 그림」 으로 지우면 엉뚱한 것이 지워졌다(10/22 실측).
- `table-split` 은 머리 줄을 나눈 표마다 되풀이한다. 표 번호는 `inspect` 의 「표 목록」 에 나온다.
  🔴 쪽을 넘는 표를 `pageBreak="TABLE"` 로 바꾸는 길은 1×1 표에서 **본문이 사라졌다**(10/22) — 나누는 것이 먼저다.
- `delete-rows`·`delete-table` 은 **원본과 결과를 둘 다 PDF 로 뽑아** ① 쪽수 변화를 보고하고(줄어도 실패 아님 — 기대가 있으면
  `--expect-pages`) ② **지운 표/줄 밖 글자가 원본과 같은지** 대조한다(XML 문단 대조 + PDF 줄 대조 — 사라진 줄은 전부 지운 것
  안이어야 하고 새로 생긴 글자는 없어야 한다). 🔴 PDF 를 못 뽑으면(`.hwpx` 출력에 `--pdf` 없음) **저장하지 않고 끝 코드 1** —
  못 잰 것을 통과로 두지 않는다. 표만 든 문단은 문단째 지운다(빈 줄이 남아 쪽이 밀리지 않게). 칸 안 표·구역 첫 문단은 표만 뺀다.
  🔴 표 제목(「…장 구성 (17~20)」)은 표 밖 문단이라 `--caption` 으로 함께 지운다. 줄을 지웠으면 제목의 범위 글자
  (「(9~16)」)는 `replace` 로 따로 고친다 — 도구가 짐작해 고치지 않는다.
- 편집 명령이 PDF 를 뽑으면 `verify` 가 **옛 글자 잔존(replace)·빨간 날짜 수(color-dates)·그림 겹침(도장 두 번)·
  빠진 그림 · PDF 축소(모아찍기)**까지 자동으로 본다. 하나라도 걸리면 실패로 끝난다.
  🔴 「PDF 축소 의심」 이 뜨면 한글 PDF 가 «2쪽 모아찍기»(0.707배)로 나온 것이다 — 그대로 제출하면 작게 나간다.
  쪽마다 A4 원래 크기로 펼친 뒤 낸다(10/18 실측).

### 그림 — **표 셀에 넣는다** (문단에 직접 붙이지 말 것)

문단에 붙인 그림은 **이미지의 픽셀 수**가 크기를 정한다. `<hp:sz>`·`<hp:orgSz>`·
이미지의 DPI 메타데이터 **셋 다 무시된다**(실측 3종). 그래서 110mm 로 보이게 하려면
416px 까지 줄여야 하고, 그 값은 **96dpi** 라 인쇄하면 거칠다.

**표 셀 안에 넣으면 셀 크기가 표시 크기를 정한다.** 원본 1025px 을 그대로 넣어도
110mm 로 잡혔다 — 같은 크기에 해상도만 96 → 237dpi.

```python
pic = H.pic_node(iid, w, h, w, h, 1, 'PARA', 'COLUMN', z=z, name=...)
tbl = H.pic_table([(pic, w, h)], tid)        # 1행 1열. 여러 개면 한 행에 나란히
xml = xml[:i] + tbl + xml[j:]                # 옛 그림 노드 자리에 끼운다
```

**예외 — 도장**: 「(서명/인)」 글자 **옆**에 찍혀야 하므로 표로 감싸면 나란히 놓을 수
없다. 도장은 그 문단의 run 뒤에 직접 붙인다(원본이 작아 화질 손실도 거의 없다).
→ 손으로 하지 말고 **`stamp` 명령**을 쓴다(자리 재기·고치기·중복 검사까지 한다).

그림을 **문단에** 붙여야 하는 경우에는 `px_for_mm` 으로 **넣기 전에 픽셀을 줄이고**,
`anchor_pic_first_para` 로 **앞쪽 문단**에 매단다.

저장 직전에 반드시:

```python
H.check_wellformed(section0=s0, hpf=hpf)     # 빼먹으면 한글이 빈 문서를 연다
H.save(작업hwpx, 결과hwpx, replaced={...}, add_files={...})
```


### 4단계 — 검수한다 (눈으로 보기 전에 숫자로)

```bash
python scripts/hwpform.py verify "<완성본.pdf>" --expect-pages <기대쪽수>
```

확인 항목: 쪽수 · 그림 크기와 위치(mm) · 종이 밖으로 넘친 줄 · 안 채운 자리 흔적.
같은 양식의 이전 완성본이 있으면 `--baseline "<기존.pdf>"` 로 대조한다.

**쪽수가 늘었으면 넘어가지 말 것.** 아래 함정 ⑦⑧⑮⑯ 중 하나다.

`verify` 가 **「안 채운 자리」**를 짚어도 그 자체가 결함은 아니다 — 사용자가 비워두기로
한 날짜·서명란이면 그게 정답이다(셀프체크 6). 채울 곳인지 **먼저 확인**한다.

마지막에 **한글로 열어 눈으로 확인**하도록 사용자에게 안내한다. 숫자 검수는
사람 확인을 대신하지 못한다.

### 안 열릴 때 — 원본을 같은 길로 한 번 통과시킨다

`to-hwp` 가 **「열기 False」** 를 내면 원인 후보는 둘이다 — ①변환 경로·도구 ②내 편집.
**아무것도 안 고친 작업본(`work.hwpx`)을 같은 명령으로 변환**해 보면 1회에 갈린다.

```bash
python scripts/hwpform.py to-hwp "<작업.hwpx>" "ctrl.hwp" "ctrl.pdf"   # 무편집 대조군
```

그게 정상으로 열리면 도구는 멀쩡하고 범인은 **내 편집**이며, 가장 흔한 것이 함정 ①이다.
이 한 번을 건너뛰면 도구·변환·환경을 의심하며 시간을 쓰게 된다.

🔴 **`check_wellformed` 통과는 무죄 증명이 아니다** — XML 이 유효해도 줄배치 값이
어긋나면 한글은 아무 말 없이 문서를 포기한다(함정 ①).

## 하지 말 것

- **`.hwp` 를 직접 고쳐 쓰기** — 한글이 그 파일을 못 연다(2/2 실측)
- **`assert all(...)` 하나로 건수 검사를 끝내기** — 대상이 비면 `all([])` 이 **True** 라 조용히 통과한다(함정 ⑭ 를 놓친 실제 경로)
- **`content.replace()` 로 XML 통째 치환** — 태그 속성까지 오염된다
- **임시 스크립트로 한글(COM)을 직접 띄우기** — 한컴은 `hwpform.py` 의 `Hancom()` 한 곳에서만 부른다
  (보안 모듈 이름 `FilePathCheckerModuleExample` · 새 한글만 띄우고 그것만 닫음 · 우리 한글의 확인창만 누름)
- **`taskkill /IM Hwp.exe`** — 사람이 열어 둔 한글까지 죽고 다음에 «문서 복구» 창이 뜬다
- **`gencache.EnsureDispatch`** — 해시별로 갈린 옛 설치 캐시를 읽고 깨진다. 동적 `Dispatch` 만
- **`&` `<` 를 그대로 넣기** — 파일이 깨진다 (`hwpx_lib` 은 자동 처리)
- **원본 양식 덮어쓰기** — 항상 사본으로 작업한다. 양식이 깨지면 처음부터다
- **값을 지어내기** — 모르는 칸은 물어본다
- **쪽수 불일치를 넘기기** — 함정 ⑦⑧⑮⑯⑰ 이 거의 확실하다
- **`hwp-mcp` 쓰기 도구**(`replace_hwp_text`·`fill_hwp_template`·`create_hwpx_document`) — 준비물 절 참조
- **여러 양식이 묶인 파일을 한 덩어리로 내기** — 양식(쪽)마다 따로 낸다. 묶음 그대로면 보기·확정·제출이 불편하고
  앵커 글자가 목차에 먼저 걸린다(사장님 6/20)

## 마치기 전 셀프체크

1. `inspect` 로 칸 주소를 **직접 확인**했는가? (라벨 칸과 값 칸을 헷갈리지 않았는가)
2. 모든 치환의 **건수**를 기대값과 대조했는가? 0건을 넘긴 곳은 없는가?
2-1. 그 검사가 **대상이 비어도 통과**하지는 않는가? (`all([])` 은 True — 키 집합까지 볼 것)
3. 저장 전에 `check_wellformed` 를 불렀는가?
4. `verify` 의 **쪽수**가 기대와 같은가? 다르면 원인을 찾았는가?
5. 그림 크기·위치를 mm 로 **재봤는가**? (지정값이 아니라 결과값)
5-1. 그림을 **표 셀**에 넣었는가? (도장 제외 — 문단 직접은 96dpi 로 흐려진다)
6. 사용자가 "비워두라"고 한 칸을 임의로 채우지 않았는가?
7. 사용자에게 **한글로 열어 확인**하도록 안내했는가?
8. 글자 서식을 손댔다면 `<hh:italic/>` 같은 **자식 요소**까지 봤는가? (속성만 훑으면 0건이 나온다)
9. 표가 쪽을 넘는 문서라면 **넘어간 쪽의 첫 행**을 실제로 봤는가? (병합 라벨이 사라진다)
10. 이번 작업에서 **임시 스크립트로 한글을 직접 띄우지 않았는가?** 없는 기능이 있었다면 이 도구에 명령으로 더했는가?
11. 옛 서류를 틀로 썼다면 **옛 회사명·날짜가 남았나**를 검사했는가? (함정 ㉑)
