# 세션 저장 (팀원용)

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 이 스킬의 범위 밖을 요청하면
> **즉시 이 절차를 그만두고 도구를 직접 호출한다.** "그만하고 그냥 만들어줘" 같은 말이 나오면
> 그 순간 이 문서의 지시는 무효다.

이번 작업을 ① **프롬프트 수집**(항상) ② **노션 팀 세션 저널 기록**(신호 있을 때) ③ **핸드오프 프롬퍼**(미완료일 때) 순으로 마무리한다.
목적: 무엇을·왜 했는지 구조화해 누적 → 검색·정리·인수인계가 쉽게 + 프롬프트를 데이터로 축적.

> 팀원용: 복잡한 정본 라우팅은 빼고 **"수집 → 5섹션 기록 → (미완료 시)핸드오프"** 에 집중한다.

## 0) 프롬프트 수집 (무조건 먼저 — 저널 여부와 무관)

이번 세션에서 친 프롬프트를 데이터 해자(`prompt_log`)로 결정론 수집한다. **적재 대상이든 아니든 항상 1회 실행.** 이 스킬 디렉토리의 `collect-prompts.js`를 Bash로:

```
node "<이 스킬 디렉토리>/collect-prompts.js"
```
- `<이 스킬 디렉토리>` = 스킬 호출 시 안내된 "Base directory for this skill" 경로.
- 출력 예: `프롬프트 N건 중 신규 X / 기존(멱등) Y / 실패 Z`. 실패·토큰없음이어도 **조용히 넘어가고** 저널은 정상 진행(수집은 부수).
- 멱등(turn_uuid) — 재실행해도 중복 안 쌓임. LLM 개입 0(결정론).

## 적재 여부 판단 (먼저 자문)

이번 작업에 **핵심 결정 / 만든 것(산출물) / 배운 점** 중 하나라도 있었는가?
- YES → 적재.
- NO (단순 질문·조회만) → "이번 작업은 기록 대상이 아닙니다" 1줄 보고 후 종료.

## 작성자 자동 확인 (적재 직전, 먼저)

공유 계정이라 "누가 했는지"는 개인 제디 토큰의 actor로 식별한다. **이름은 서버가 알려준다**(2026-07-29~ — 파일 명단이 아니라 백엔드 `actor.name`). 적재 직전 **딱 1회** Bash로 실행:

```
node "$HOME/.claude/plugins/marketplaces/zulgap-team-pack/teampack-config.js" name
```
- 위 경로가 없으면 `~/.claude/plugins` 아래에서 `teampack-config.js`를 찾아 실행한다(캐시 경로 환경차).
  (구버전 호환: `resolve-staff.js`도 같은 값을 준다 — 내부에서 위 스크립트로 위임)
- 출력된 **이름 한 줄**을 아래 `작성자` 속성에 넣는다.
- 출력이 **비어 있으면** `작성자`는 **생략**하고 저널은 정상 적재한다. 다만 이건 정상 상태가 아니다 —
  🔴 **토큰이 없거나 서버에 닿지 못한 것**이므로 사장님께 알린다(전원 토큰 발급이 원칙).
  stderr에 `🔴 캐시가 N일 지났습니다` 경고가 뜨면 그대로 보고할 것.

## 적재 방법

`notion-create-pages` 호출:
- **parent**: `{"type":"data_source_id","data_source_id":"<아래 명령의 출력>"}`
  ```
  node "$HOME/.claude/plugins/marketplaces/zulgap-team-pack/teampack-config.js" notion.team_journal_ds
  ```
  (하드코딩 금지 — 회사마다 DB가 다르다. 출력이 비면 사장님께 온보딩 요청)
  - (줄갭 "팀 세션 저널" DB — 마스터 허브 하위. 직원이 이 DB에 노션 권한이 있어야 적재됨)
- **properties**:
  - `세션` (title): 이번 작업 한 줄 제목
  - `작성자`: 위에서 얻은 이름 (비면 생략)
  - `date:날짜:start`: 오늘 날짜 (YYYY-MM-DD), `date:날짜:is_datetime`: 0
  - `유형`: 콘텐츠제작 / 조사 / 문서작성 / 기타 중 1개
  - `한줄 요약`: 이 작업에서 가장 중요한 것 1줄
  - `산출물`: 만든 것(링크·파일명)
- **content (body) = 표준 5섹션 고정**:
  ```
  ## 배경 / 요청
  무엇을 하려 했는가 (1~2줄)

  ## 핵심 결정 + 근거
  무엇을 정했고 왜

  ## 학습 · 함정
  하면서 알게 된 것, 다음에 조심할 것

  ## 산출물
  만든 콘텐츠 / 문서 / 링크

  ## 미해결 · 다음
  다음에 이어서 할 것
  ```

## 🔴 적재 직후 — 한글 되읽기 대조 (필수, 인덱싱 «전»)

노션 MCP 인자에 한글을 `\uXXXX` 로 넘기면 **받침 한 칸이 어긋난 글자**가 조용히 섞인다.
도구는 성공을 반환하고 반환값에도 안 보인다. 저널은 나중에 «근거»로 읽히는 문서라,
글자 하나가 틀어지면 그때 판단이 틀어진다.

> **2026-08-26 실측** — 이 스킬로 적재한 세션 저널 한 장에서 **8곳**이 틀어졌다
> (`못 바꿔다`·`뜼면`·`박혔`·`끕」이 곳`·`썹네일`×2·`결들여`·`셀고`).
> 같은 날 카드 6장에서도 12곳이 났다. 경고문은 그때까지 다섯 번 실패한 상태였다.

**한글은 그대로 친다.** 그리고 적재한 뒤 **반드시 되읽어 대조한다.**

```
① 5섹션 본문을 «파일로 먼저 쓴다»                sent.md
② 그 파일 내용을 그대로 notion-create-pages 에 넘긴다
③ notion-fetch 로 되읽어 파일로 저장하고 대조     got.md
```

```bash
diff -u sent.md got.md          # 다르면 그 줄이 통째로 나온다. 오탐 0
```

🔴 **섹션 개수나 표 행 수만 세면 못 잡는다** — 틀어지는 자리는 «평범한 문장 한가운데»다.
🔴 **고칠 때 `old_str` 은 화면에서 그대로 복사한다** — 다시 이스케이프로 치면 같은 자리에서 또 틀어진다.
⚠️ 속성값(`세션`·`한줄 요약`·`산출물`)도 같다. 본문만 보고 넘어가지 말 것.

## 적재 직후 — 검색 인덱싱 (필수, 딱 1회)

🔴 **노션에만 쌓으면 나중에 검색이 안 된다.** 적재 응답의 **page id**로 아래를 실행:

```
node "$HOME/.claude/plugins/marketplaces/zulgap-team-pack/journal-ingest.js" "<page_id>" "<세션 제목>" "<한줄 요약>"
```
- 이걸 해야 나중에 `/시작`의 과거 회상이나 제디가 이 기록을 **찾을 수 있다**.
- **작성자 귀속은 서버가 토큰으로 한다** — 이름을 보내지 않는다(보낼 필요도 없다).
- 실패해도 저널은 이미 노션에 적재됐다. 출력을 **그대로 보고만** 하고 넘어간다.
- 같은 저널을 고쳐서 다시 부르면 그때만 재인덱싱된다(멱등).

## 캡처 원칙 (노이즈 차단)

- **담아라**: 핵심 결정·근거 / 만든 것 / 배운 점.
- **빼라**: 도구 실행 로그 / 중간 과정 / 뻔한 것.
- **형식 일관성 = 매번 같은 5섹션** (나중에 검색·정리가 쉽다).

## 핸드오프 프롬퍼 (작업이 아직 안 끝났으면)

저널 기록 후 **"이 작업이 다 끝났나"** 를 자문한다. 아래 중 하나라도 해당하면 = 미완료 → 다음 세션이 바로 이어갈 **핸드오프 파일**을 만든다:
- ⬜ 만들던 게 중간에 끊김 (일부만 완성 / 검증 안 함)
- ⬜ 다음에 이어서 해야 할 게 남음
- ⬜ 누구 답·외부 자료를 기다리는 중

**전부 끝났으면** → 만들지 않고 "작업 완결 — 핸드오프 불필요" 1줄 보고.

미완료면 `~/.claude/specs/YYYY-MM-DD-handoff-<작업한단어>.md` 에 아래 **6블록**으로 작성:
```markdown
# 핸드오프 — <작업명>

> 상태: 🔵 진행          ← 🔴 필수 1줄. `/jedi-start` 가 이 줄로 「살아있는 작업」을 고른다
> 완료조건: pr:239 · human:대표님-확인   ← 🔴 필수 1줄. 아래 § 완료조건 참조

## 한 줄
<무엇을 하면 이 작업이 끝나는가 — 1문장>

## 🗺 로드맵 (이 작업이 큰 그림에서 어디쯤인가)
<아래 "로드맵 블록" 참조>

## 다음에 바로 할 것 (복붙 프롬프트)
<다음 세션 첫 발화로 그대로 붙여넣을 프롬프트>

## 지금까지 한 것
<완성된 것 / 결정한 것>

## 남은 것
<⬜ 남은 항목>

## 조심할 것
<손대면 안 되는 것 / 함정>
```
작성했으면 그 경로도 완료 보고에 포함한다.

### 🔴 완료조건 한 줄 — 「끝났나」를 기계가 검사하게 (필수)

**왜 필요한가**: 「진행 중」이 쌓이는데 무엇이 끝났는지 세는 자리가 없다. 「끝났다」라는 **낱말로 찾으면 안 된다** — 실측 18건 중 **16건이 오탐**이었다(전부 *"X는 끝났다, **남은 것은** Y"* 형태). 낱말로는 원리적으로 못 가른다. 그래서 **쓸 때 기계가 읽을 수 있게** 적어 둔다.

**문법 — 축을 `·` 로 잇는다**

```
> 완료조건: pr:239 · commit:ac93d27@origin/main · file:plugins/x/y.md · human:대표님-확인
```

| 축 | 뜻 | 검사 방법 |
|---|---|---|
| `pr:N[,M]` | 그 PR 전부 머지 | `gh pr view` 로 MERGED 확인 |
| `commit:<sha>[@<ref>]` | 커밋이 그 브랜치에 포함 (기본 `origin/main`) | 팀팩 레포에서 확인 |
| `file:<경로>` | 파일 실재 | `~`=홈 · 절대경로 · 그 외는 팀팩 레포 상대 |
| `human:<한 줄>` | **사람만 아는 것** | 🔴 **검사하지 않는다.** 그대로 보여준다 |

**🔑 `human:` 이 대부분인 것이 정상이다.** 이 규약의 값어치는 「자동으로 닫는 것」이 아니라 **「내가 할 일 / 남의 답 대기 / 진짜 끝남」이 매번 자동으로 갈리는 것**이다.

- `human:` 은 **한 줄로 구체적으로**. `human:확인` ❌ → `human:대표님-발행승인` ✅
- 사람이 할 일이 없으면 `human:` 을 **쓰지 않는다**(쓰면 영원히 「답 대기」에 남는다)
- 기계 축이 하나도 없어도 된다 — `> 완료조건: human:동료사-피드백-수령` 도 완전한 한 줄이다

**검사**

```bash
node plugins/jedi-core/skills/jedi-save/handoff-done-check.js          # 사람용 요약
node plugins/jedi-core/skills/jedi-save/handoff-done-check.js --json   # /jedi-start 가 읽는 형태
```

판정 5종: `ready`(기계 조건 전부 충족 + human 없음) · `waiting_human` · `in_progress` · **`unknown`**(검사 실패 — 🔴 「미충족」이 **아니다**) · `no_condition`(이 줄이 없는 옛 파일).

🔴 **`unknown` 을 `ready` 로 올리지 않는다** — `gh` 미설치·네트워크 실패로 **못 잰 것**을 「충족」으로 읽으면 안 끝난 작업이 닫힘 후보로 올라간다. 반대로 「미충족」으로 뭉개도 끝난 작업이 영원히 열린다.

⚠️ **소급하지 않는다** — 옛 핸드오프에 몰아서 채우지 말 것. 살아있는 작업은 어차피 `/jedi-save` 를 다시 타므로 그때 채워진다. 안 열리는 것은 채울 필요가 없다.

### 🔴 상태 줄 + 끝난 핸드오프 닫기 (필수)

핸드오프 파일은 **계속 쌓인다.** 그런데 「끝난 것」과 「아직 하는 중인 것」을 가르는 표시가 없으면, 나중에 `/jedi-start` 로 이어받을 때 **이미 끝난 작업까지 후보로 나와** 뭘 골라야 할지 알 수 없다.

#### ① 내 핸드오프에 상태 1줄

| 값 | 뜻 |
|---|---|
| `🔵 진행` | 아직 하는 중 — `/jedi-start` 후보 |
| `✅ 종결 (YYYY-MM-DD)` | 끝남 — 후보에서 빠짐 |
| `✅ 종결 (YYYY-MM-DD) → 후속: <파일명>` | 끝났고 **다른 핸드오프가 이어받음** |

#### ② 🔴 이어받은 앞 핸드오프도 닫는다 (양쪽 다 적어야 한다)

이번 핸드오프가 **앞 핸드오프를 이어받은 것**이면, **그 앞 파일에도 종결 줄을 적는다.**

```markdown
# 핸드오프 — 카드 명세서 정리
> 상태: ✅ 종결 (2026-08-08) → 후속: 2026-08-08-handoff-card-ledger.md
```

🔴 **한쪽만 적으면 소용없다.** 새 파일에 "앞 작업: ○○" 이라고 적어도, `/jedi-start` 는 **최신순으로 읽어서 앞 파일을 먼저 만난다** → 이미 끝난 작업을 처음부터 다시 시작한다.

**닫아야 할 때** — 하나라도 해당:
- 이번 핸드오프가 그 작업을 이어받음
- 그 작업이 실제로 다 끝남
- 그 작업을 접기로 함

**닫지 말 것**: 잠깐 미뤄둔 작업(= 여전히 `🔵 진행`). **오래됐다고 끝난 게 아니다.**

⚠️ **다 이어받은 게 아니면 닫지 말 것** — 앞 핸드오프의 「남은 것」 중 **새 문서로 안 옮긴 항목**이 있으면 그건 *일부만* 이어받은 것이다. 닫으면 그 항목들이 통째로 사라진다. 닫기 전에 **「남은 것」을 새 문서와 대조**한다.

#### ③ 🔴 묵은 작업 3건 되묻기 (2026-08-13 신설 — 매번 실행)

**왜 필요한가**: 위 ②는 *"이어받을 때 닫아라"* 인데, 실제로는 잘 안 닫힌다. 이유가 구조적이다 —
**이어받은 사람은 앞 문서가 있는지도 모르고**(다른 창에서 만든 파일이다), 닫는 일이 **자기 결과물이 아니라** 뒤로 밀리며, **끝났는지 판정도 애매하다.**

사장님 환경 실측(2026-08-13) — 「진행 중」 **55건** 중 **24건(44%)이 3일 이상 방치**됐고 그중 넷은 명백히 끝난 작업이었다. 그래서 `/jedi-start` 가 매번 55줄을 내놓고 **어느 걸 이어야 할지 알 수 없게** 됐다.

∴ *"이어받을 때 닫아라"* 만으로는 부족하고 **주기적으로 되묻는 자리**가 필요하다. `/jedi-save` 가 그 자리다.

**조회 (매번 1회 · 3건만)**

```bash
cd ~/.claude/specs
export LC_ALL=C
CUT=$(date -d '3 days ago' +%Y-%m-%d)
grep -l '^> *상태: *🔵' *handoff*.md 2>/dev/null | grep -v autohandoff | while read f; do
  d=$(echo "$f" | grep -oE '^[0-9]{4}-[0-9]{2}-[0-9]{2}')
  [ -n "$d" ] || continue    # 🔴 날짜를 못 읽으면 묻지 않는다(빈 값은 어떤 날짜보다 작아 전부 걸린다)
  [[ "$d" < "$CUT" ]] || continue
  # 🔴 상태 줄의 «뒷말»을 함께 뽑는다 — 「일부만 이어받았지 끝난 게 아님」이 여기 적힌다
  st=$(grep -m1 '^> *상태:' "$f" | sed 's/^> *상태: *//')
  # 🔴 최근에 「살아있어」 라고 답 들은 것은 건너뛴다 — 아래 표의 «3일간 다시 안 묻는다» 를 실제로 하는 곳
  #    이 줄이 없으면 그 약속이 말로만 있고 안 지켜진다. 게다가 오래된 순으로 줄을 세우니
  #    이미 확인한 것이 앞자리를 계속 차지해 뒤에 있는 것들이 영영 안 보인다
  #    (2026-08-18 실측: 3일 넘은 71건 중 4건이 앞 3자리를 막아 67건이 한 번도 안 나왔다)
  #    sort|tail -1 = 여러 번 확인받아 날짜가 여러 개 적혀도 «가장 최근» 것을 고른다
  cdate=$(echo "$st" | grep -oE '확인 [0-9]{4}-[0-9]{2}-[0-9]{2}' | grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}' | sort | tail -1)
  if [ -n "$cdate" ] && [[ ! "$cdate" < "$CUT" ]]; then continue; fi
  # 🔴 「## 한 줄」에서 메타 문장을 건너뛰고 **굵게(**) 로 시작하는 실질 문장**을 고른다.
  #    ⚠️ cut -c 로 자르지 말 것 — LC_ALL=C 라 한글이 바이트로 잘려 마지막 글자가 깨진다(실측)
  body=$(sed -n '/^## 한 줄/,/^## /p' "$f" | grep -v '^##\|^$\|^--\|^> \|^~~' | grep -v '⟳')
  one=$(echo "$body" | grep '^\*\*' | head -1)
  [ -n "$one" ] || one=$(echo "$body" | head -1)   # 굵은 줄이 없으면 첫 줄
  # 🔴 머리 15줄에 「닫지 말 것」류가 있으면 표시 — 파일이 스스로 한 말을 무시하지 않게
  w=""; head -15 "$f" | grep -qiE '종결 아님|닫지 말|닫으면 통째로' && w=" 🔴닫지말것"
  echo "$d|$f|$st$w|$one"
done | sort | head -3
```

⚠️ **출력은 한 줄로 두고 `sort` 뒤에 사람이 나눠 쓴다** — 반복문 안에서 2줄로 나눠 찍으면 `sort` 가 들여쓴 줄을 앞으로 끌어올려 **짝이 어긋난다**(실측).

**보여주기 (최대 3건)**

🔴 **`상태:` 줄을 반드시 함께 보여준다** — 뒷말에 「일부만 이어받았음」·「뒷 문서가 안 받았음」 같은 **닫으면 안 되는 이유**가 적혀 있다.

```
📁 오래된 작업 확인 (3일+ 손 안 댐 · 전체 N건 중 3건)
   1. [8/07] 파일 인입   🔴닫지말것
      상태: 🔵 진행 — 일부만 이어받았지 끝난 게 아님 (8/08 판정)
      한 줄: 지금 남은 것은 «사람이 해야 할 6건» — 이게 없으면 전량 인입을 못 돌린다
   2. [8/08] 귀속 갭
      상태: 🔵 진행
      한 줄: 어디에 쌓이는지 지도로 확정한 뒤 처방을 정하면 완결
   → "1번 끝났어" / "2번은 살아있어" 하시면 그 자리에서 표시합니다
```

**닫기 (사람이 말할 때만)**

| 말 | 하는 일 |
|---|---|
| "N번 끝났어" | 그 파일 머리에 `> 상태: ✅ 종결 (오늘) — 확인함` 을 **한 줄 고침** |
| "N번은 살아있어" | 머리에 `(확인 <오늘>)` 을 덧붙여 **3일간 다시 안 묻는다** — 🔑 **위 조회의 `cdate` 줄이 이걸 실제로 하는 곳**(2026-08-18 추가. 그전엔 약속만 있고 읽는 코드가 없어 안 지켜졌다) |
| 아무 말 없음 | **아무것도 안 한다.** 다음에 또 뜬다 |

**함정**
- 🔴 **내가 알아서 닫지 말 것.** 끝났는지는 코드로 판정할 수 없고, 잘못 닫으면 **살아있는 작업이 `/jedi-start` 후보에서 영영 빠진다**(길 잃는 것의 반대 방향 사고). 사람이 말한 것만 근거다
- 🔴 **「한 줄」을 읽고 「끝난 것 같다」고 제안하지 말 것.** 실제로 두 번 틀렸다 — 어떤 파일의 한 줄 첫 문장이 *"⟳ 갱신 — 원래 한 줄이 이미 해결된 것을 가리키고 있었다"* 라 **「이미 해결」로 읽고 닫자고 제안**했는데, 그건 «한 줄이 낡았었다»는 뜻이지 «작업이 끝났다»가 아니었다. 같은 파일 머리 3줄 위에 **「일부만 이어받았음 … 닫으면 통째로 사라진다」** 가 적혀 있었다.
  🔑 **파일이 스스로 「닫지 말라」고 말하는 자리는 `## 한 줄` 이 아니라 머리의 `상태:` 줄이다.** 그래서 위 조회가 상태 뒷말과 `🔴닫지말것` 을 함께 뽑는다. **그 둘을 안 보고 닫기를 제안하면 규약 위반.**
- 🔴 **3건을 늘리지 말 것.** 하루에 여러 번 저장하므로 **며칠이면 밀린 것이 다 정리된다.** 한 번에 20건을 올리면 그게 바로 「긴 목록 앞에서 고르는 일」의 재현이다
- ⚠️ **0건이면 이 블록을 통째로 생략**한다
- ⚠️ `/jedi-start` 는 **접기만 하고 닫지 않는다** — 그쪽은 읽기 전용이라 **여기가 유일하게 고치는 자리**다

### 🗺 로드맵 블록 (필수)

**왜 필요한가**: "남은 것"은 *이 작업 안*만 말한다. 다음 세션은 그걸 읽고 일은 이어가지만 **"이게 왜 필요한 일인지"를 모른 채** 이어간다 → 큰 방향과 어긋나게 완주하거나, 이미 접은 갈래를 붙잡는다. 로드맵은 *할 일*이 아니라 **좌표**를 넘긴다.

**3가지를 답한다** (모르면 빈칸·추측 대신 `⚠️ 미확인 — <확인 방법>`):

| # | 질문 | 쓰는 법 |
|---|---|---|
| 1 | **이 작업이 속한 더 큰 일이 뭔가** | 상위 문서·노션 페이지 **링크만** 적는다(내용 복사 금지 — 복사하면 두 곳이 갈라진다). 없으면 **"단독 작업 — 상위 없음"** 이라고 명시. 🔴 **링크만 적고 넘어가지 말 것 — 아래 1-A** |
| 2 | **전체 중 어디인가** | 단계를 나열하고 현재 위치 표시: `✅ 완료 / 🔵 현재 / ⬜ 예정` |
| 3 | **앞뒤 연결** | 선행(뭐가 끝나야 이게 됨) + 후행(이게 끝나면 뭐가 열림). 없으면 "없음" |

마지막에 **"한 줄로"** — 큰 일과 이 작업의 관계를 한 문장으로.

**예시**:
```markdown
## 🗺 로드맵

**상위**: 노션 「7월 카드뉴스 개편」 (링크)
**전체 중 현재 위치**:
| 단계 | 상태 |
|---|---|
| 1 템플릿 확정 | ✅ 완료 |
| 2 이 작업 (본문 카피) | 🔵 3/5장 완료 |
| 3 최종 검수·발행 | ⬜ 예정 |

**앞뒤 연결**: 선행 없음 / 후행 — 5장 다 돼야 검수 넘어감
**한 줄로**: 개편 전체 중 본문 파트. 템플릿은 이미 고정이라 그대로 쓰면 된다.
```

**함정**:
- ⚠️ 상위 문서 **내용을 복사하지 말 것** — 링크만. 복사하면 나중에 두 곳 내용이 달라진다
- ⚠️ 단계 목록은 **상위 문서에 실제로 있는 단계**를 쓸 것. 그럴듯하게 지어낸 단계는 다음 세션을 더 헤매게 만든다 — **상위 문서를 실제로 열어보고 쓴다**
- ⚠️ 상위에 없는 분류·라벨을 **만들어 붙이지 말 것**. 한 번 적히면 다음 세션이 사실로 믿는다
- ⚠️ **로드맵은 「내 작업」만 그린다** — 다른 사람·다른 작업의 진행 상황을 곁다리로 적지 말 것. 남길 가치가 있는 건 딱 둘이다: ① **같은 파일을 다른 사람도 고치는 중**(부딪히면 사고) ② **그게 끝나야 내가 되는 것**(앞뒤 연결). 판정 1줄 = *"이걸 모르면 다음 세션이 잘못 움직이나?"* — 아니면 뺀다. 로드맵은 *현황 보고*가 아니라 **좌표**다

#### 🔴 1-A. 위 표 1번을 적을 때 — 상위 문서가 낡았는지도 본다

**한 주제를 여러 날에 나눠 하면 상위 문서가 조용히 낡습니다.** 그동안의 진행은 매번 **핸드오프에만** 쌓이고, 정작 "이 일 전체가 어떻게 되고 있나"를 담은 문서는 며칠 전에서 멈춰 있습니다.

🔴 **링크는 매번 성실히 적혀 있습니다.** 문제는 **적는 것**과 **그 링크가 아직 맞는지 보는 것**이 다른 일이라는 겁니다. 후자가 없으면 나중에 누가 *"이거 전체 어떻게 돼가?"* 라고 물었을 때 **문서 대여섯 개를 열어야** 답이 나옵니다.

**언제** — 이 주제를 **3세션 이상** 이어서 하고 있을 때만. 오늘 시작해 오늘 끝나는 일은 해당 없습니다.

**어떻게 (30초)**

| 상위 문서 | 마지막 갱신 확인법 |
|---|---|
| 노션 페이지 | 페이지 맨 아래 **"마지막 편집"** 또는 상단 `⟳ / 갱신:` 표기 |
| 핸드오프 파일 | 헤더의 `> 작성:` 날짜 |

그 날짜를 **이 주제의 최근 진행**과 비교합니다.

| 상황 | 할 일 |
|---|---|
| 상위가 더 최신이거나 비슷 | 링크만 적고 넘어감 ✅ |
| **상위가 더 오래됨** | 🔴 **상위 문서 맨 위에 「최신 정리」를 먼저 추가**하고, 핸드오프는 그걸 가리킨다 |

**「최신 정리」에 담을 4가지** (이보다 줄이지 마세요 — 이게 「그 주제의 큰 그림」입니다):

1. **여기까지 온 순서** — 언제 무엇이 어디로 넘어갔나 (날짜순)
2. **이 일의 구조** — 축·단계가 몇 개고 각각 무슨 상태인가
3. 🔴 **뒤집힌 것** — 앞에 적힌 것과 **결론이 달라진 것**. *"인용하기 전에 여기부터"* 라고 적어둘 것
4. 🔑 **지금 당장 할 수 있는 것** — 「할 수 있나 / 막는 게 뭔가」 2열. **막힌 것과 지금 되는 것을 갈라 놓습니다**

**함정**
- ⚠️ **새 문서를 만들지 마세요** — 큰 그림이 둘이 되면 그게 더 헷갈립니다. **기존 문서 맨 위에 덧붙입니다**
- ⚠️ **맨 위에 두고 "아래보다 최신"이라고 적으세요** — 뒤에 붙이면 낡은 부분을 먼저 읽습니다
- ⚠️ **끝난 핸드오프의 「다음에 할 것」을 그대로 옮기지 마세요** — 진행 도중 무효가 된 것이 섞여 있습니다

**표시 방법**:
- **프롬프트**는 *지금 남은 일*로 바꾼다. 끝난 지시는 **지운다**(「했음」으로 남기지 말 것 — 실행 대상이라 군더더기가 곧 오작동)
- **저널**은 새 행을 만들지 말고 기존 페이지 **맨 끝에 `## ⟳ 저장 후 갱신` 을 덧붙인다**. ⚠️ 본문 일부를 찾아 바꾸려 하면 노션이 표를 다르게 저장해 실패한다 — 덧붙이기가 정답

- 변동 없으면 **"⟳ N회차 재검증 — 변동 없음"** 한 줄로 명시한다 (*확인했는데 없음*과 *확인 안 함*은 다르다)
- 로드맵이 바뀌면 **"한 줄로" 요약도 같이 고칠 것** — 표만 고치고 결론을 놔두면 둘이 어긋난다
- **`상태:` 줄** — 이번에 그 작업이 **끝났으면** 그 자리에서 `✅ 종결 (오늘) [→ 후속: <파일>]` 로 바꾼다. 다음 `/jedi-save` 로 미루면 그 사이에 `/jedi-start` 가 **끝난 작업을 집어온다**
