# 썸네일 — 대본 → 기획 3안 → 대화 수정 → 생성 (팀원용)

대본을 주면 **미스터비스트 후킹 공식**으로 썸네일 기획안 3개를 뽑고, 네가 대화로 고른/고친 뒤 **완성 썸네일**(배경 + 정확한 한글 텍스트)을 만들어 준다.

> **핵심**: 텍스트는 GPT가 그림 안에 그리면 한글이 깨진다 → 이 스킬은 **배경만 GPT Image 2로 생성 + 글자는 HTML 오버레이**로 얹어 **픽셀 정확**하게 만든다.
> **제디(jedi) 도구가 활성일 때만 동작** — 개인 `JEDI_TOKEN` 필요.

## 입력 판별 (먼저 이것부터)

| 입력 | 처리 |
|---|---|
| **대본** (필수) | STEP 1~3으로 기획 3안 생성 |
| **채널명** (선택) | **채널 위키를 읽어 코어 위에 적용** — 찾는 순서는 § 채널 위키 참조 |
| **인물 사진** (선택, 로컬 경로/첨부) | 배경 생성 시 그 인물 합성 (얼굴 유지) |

채널 위키가 없으면 범용 기본값으로 진행. 있으면 **반드시 먼저 읽고** 타깃/갭언어우선순위/배경무드/금칙/인물규칙을 적용.

## 🧭 알고리즘 (대본 → 기획안 3안)

### GATE 0 — 5대 기반 법칙 (모든 안이 먼저 통과, 위반 시 폐기)
1. **극단성**: 평범→흥미→극단 사다리 (앞마당50시간❌→케첩속50시간✅ / Spent→Survived)
2. **기대치 계약**: 대본이 실제로 지킬 약속인가? **클릭만 끌고 못 지키는 낚시 금지**
3. **단순성**: 3초·한 메시지·요소 욕심 없음
4. **Wow**: 남들 못 하는 각 1개
5. **핵심요소**: 썸네일 = 영상 설계도 (산출물 아님)

### STEP 1 — 대본 분석
- 타깃(채널 위키가 있으면 그 페르소나) · 핵심 메시지 1문장 · **의외 소재 후보 3개**(경험자/재도전/실패후/통념깨기 우선) · 감정축(불안·기대·놀라움)

#### 🔴 STEP 1-A. 제목을 «먼저» 읽는다 — 썸네일은 제목의 짝이다 (2026-09-05 신설, 게이트)

> 🔴 **왜 신설**: 종전에는 이 관계가 STEP 3 체크리스트의 **한 줄**(*"제목은 썸네일보다 딱 한 단계만 더 설명하나?"*)
> 뿐이었다. 체크박스는 스스로 통과 선언이 되므로 게이트가 아니고, **「한 단계」가 무엇인지 정의도 없었다.**
> 🔴 **실사고 (2026-09-05)**: 대본에 **제목 확정안이 이미 있는데** 그것을 안 읽고 썸네일만 짰다.
> 결과로 3안 중 하나는 서브카피가 **제목 앞부분을 그대로 복사**했고, 다른 하나는 **제목 전체를 압축**한
> 같은 말이었다. 두 칸(제목·썸네일)이 한 칸이 되어 시청자가 받는 정보가 절반으로 줄었다.
> 사장님 지적으로 잡혔다 — *"'제목'과 같이 고려해야 합니다."*

**① 대본에 제목이 있으면 그것부터 읽는다.** 대본 § 메타에 「제목 (확정안)」·「제목 (대안 N)」이
있으면 **그것이 출발점**이다. 새로 짓지 않는다 — 이미 사람이 정한 약속이다.
없을 때만 `:58` 규칙으로 짓는다.

**② 역할 분담 — 세 칸은 서로 다른 것을 말한다**

```
썸네일  →  제목  →  본문
  장면      맥락     이유
 (3초)   (누구·뭘)  (왜)
```

**③ 🔴 중복 게이트 — 제목과 썸네일이 같은 정보를 말하면 그 안은 폐기**

3안 제시 시 각 안마다 **아래 한 줄을 채운다. 빈칸이거나 「같음」이면 폐기하고 다시.**

```
제목이 말하는 것: [        ]
썸네일이 거는 것: [        ]   ← 위와 달라야 한다
```

**판정 1줄 룰**: *"제목을 읽은 사람이 썸네일에서 새로 알게 되는 것이 있나?"* 없으면 중복이다.

| | 예 |
|---|---|
| ❌ bad | 제목 「사별 4년, 일곱 살 아들…38세 초혼 남성이 먼저 손을 내밀었습니다」<br>서브 「사별 4년, 일곱 살 아들을 둔 그녀」 ← **제목 복사** |
| ❌ bad | 같은 제목 + 메인 「가장 어렵다던 조합에 / 초혼 남성이 먼저 왔다」 ← **제목의 압축** |
| ✅ good | 같은 제목 + 메인 「신청서 어느 칸에도 / '결혼'이 없었다」<br>← 제목이 **안 말한** 회수 장치를 건다 |

**④ 제목이 정보를 많이 줄수록 썸네일은 「대본이 심어둔 회수 장치」로 간다.**
대본에 *"~를 예고로 심기"* · *"결과는 숨김"* 이라 적힌 장치(핵심 단어·숫자·물건)가 있으면
**그것이 썸네일의 1순위 후보**다. 제목은 상황을 말하고 썸네일은 **그 장치가 있다는 사실만** 보여준다.

### STEP 2 — 기획안 3개 생성 (대본 성격에 따라 갭언어 전략 적응 선택)
각 안 = 아래 4요소. **대본 성격에 맞춰 서로 다른 갭언어 유형 3개**를 AI가 선택(고정 분산 아님):

| 요소 | 규칙 |
|---|---|
| **제목**(영상용) | 경험자 명시 + 페르소나(예 "33세 약사") + "실제 사례". 결론 스포·과도 디테일·AI체 금지 |
| **메인카피**(썸네일 후킹) | 🔴 **한 줄당 9~13자** — 2줄이면 총 18~26자. 구(phrase), 질문형/미완성형, **스포 금지**, 숫자·'이것' OK(정답 스포만 금지). 강조할 1단어(또는 아랫줄 전체) 표시 |
| **서브카피**(하단 자막) | **14~22자**, 사례로 고정 — 페르소나/시간("N년 만에")/상황 중 2~3개 |
| **배경컨셉** | 무드로 신뢰(상담실/대화/노트 등). 채널 위키의 인물 규칙 적용 |
| **레이아웃**(A/B/C) | 대본 성격으로 자동 선택 (아래 표) |

> 🔴 **줄당 5자짜리 카피를 쓰지 말 것** (2026-07-30 실측 교훈). 짧은 카피로 화면 폭을 채우려면 auto-fit이 폰트를 2배로 키우고, 그러면 **글자가 세로까지 먹어 배경 이미지가 안 보인다.**
> 실측 대비: 한방언니(43만) **줄당 10자** ("남자들이 결혼 직전에" / "파혼하는 진짜 이유 3가지") ↔ 실패 사례 **줄당 5자** ("세대 차이라" / "안 될 줄").
> 줄당 9~13자를 채우면 폰트가 자연히 적정해지고 정보량도 늘어난다. **글자 크기는 카피 길이가 결정한다.**

**갭언어 9종**(대본 성격에 맞춰 3개 선택) — 🔴 **먼저 `references/copy-theory.md` §1 을 읽는다.** 9종 이름·리터럴·쓰는 자리는 그 파일이 정본이고 여기엔 복제하지 않는다(두 곳에 두면 갈라진다 — 2026-09-20 실측: 이 자리에 **8종**으로 적혀 있었고 「이유방법비법」이 「이유·방법」으로 개명돼 있었다). 각 안에 유형 태그를 붙여 제시.

### 🧠 카피 작법 — 탑다운 + 바텀업

🔴 **원리·예시는 `references/copy-theory.md` §2·§3 이 정본** — 탑다운(평소 «관심 있는» 말로 페르소나를 불러세운다) / 바텀업(S+V+P — 주어·동사·장소 중 **하나만** 비튼다). 스틱 6요소 적용 순서는 §4, 판정축 3개(의외성·공감성·구체성)는 §5. 여기서는 아래 게이트로 «썼는지»만 강제한다.

### 🚧 의외성 게이트 — 3안 각각 이 표를 **채워서 제시**한다 (빈칸이면 그 안 폐기)

> 🔴 **이건 권고가 아니라 출력 형식이다.** *"의외성을 넣으세요"* 같은 자연어 당부는 **실제로 안 지켜진다** —
> 2026-07-30에 이 지시문을 쓴 직후 같은 세션에서 `14살 차이라 안 될 줄 / 세 번 만에 교제했습니다`(비튼 것 0, 결론 스포)를 그대로 제출했다.
> 운영 검수에서 *"카피에 의외성이 전혀 없네요"* 로 잡아냈다. **표를 강제하지 않으면 반드시 재발한다.**

3안 제시 시 각 안마다 아래 3줄을 **반드시 함께** 출력한다:

```
비튼 것: 주어 / 동사 / 장소 중 [        ]   ← 지목 못 하면 폐기하고 다시
깨는 통념: "사람들은 보통 ____라고 생각한다" ← 못 쓰면 비튼 게 없는 것
결론 스포: 없음 / 있음                      ← "있음"이면 폐기
```

**금지 리터럴 — 아래가 메인카피에 들어가면 결론 스포로 간주하고 폐기**
1. `~했습니다` / `~됐습니다` 로 **결말을 완료형으로 서술** (예: "세 번 만에 교제했습니다")
2. `정답은` · `이유는 ~때문` · `결국 ~였다`
3. `~가 답입니다` (정본 반례: *"'매력'이 답입니다"* 는 의외성 부족으로 시선을 못 끈다)
4. 대본의 **결말·해결책**을 그대로 옮긴 문장

**good / bad 예시쌍 (2026-07-30 실사례)**

| | 카피 | 판정 |
|---|---|---|
| ❌ bad | `14살 차이라 안 될 줄 / 세 번 만에 교제했습니다` | 비튼 것 **0** + 결말 완료형 서술 = 사실 나열 |
| ✅ good | `42살이 28살에게 / "저도요"라고 했다` | **동사** 비틀기(연상이 배우는 자세) · 무슨 뜻인지 안 말함 |
| ✅ good | `14살 위인데도 / 가르치지 않았습니다` | **동사** 비틀기(나이 많으면 가르친다는 통념) |
| ✅ good | `나이 얘기는 / 딱 두 번 나왔다` | **동사+숫자**(나이차 커플은 나이 얘기가 끊이지 않는다는 통념) |

**탑다운도 함께 확인** — 이 카피를 보고 **누가** 자기 얘기라고 느끼나? 한 문장으로 못 쓰면 페르소나가 안 걸린 것.

**카피 재미(유머) 강도** (실측 피드백 2026-07-26, 팀 지연): "클릭·구독 유도되게 더 재밌게, 단 과하지 않게" 요청 시 아래 기법으로 재치를 더한다 — 단 **채널 톤을 넘지 않는다**(예: 멘토 톤 채널이면 불안·과장 조장 금지):
- **아이러니/반전**: "잘해준 게 죄였습니다" (착한 행동이 원인이라는 반전)
- **의인화**: "썸이 도망간다" (추상적 현상을 행동 주체처럼)
- **말장난**: "속도위반" (실제 상황과 관용구를 겹쳐 웃음 포인트)
- **사회적증거 유형일 때 배치**: 체크리스트·자가진단은 **메인이 아니라 서브카피로 내리고**, 메인은 더 강한 한 줄 훅으로. (예: 메인 `차인 이유 다 똑같았다` / 서브 `5개 중 3개면 당신도 해당됩니다` — 반대로 메인에 체크리스트 숫자를 놓으면 심심해진다)

### 🔴 배경지식 게이트 — 대본을 안 본 사람이 3초에 이해하나 (2026-09-05 신설, 게이트)

**썸네일을 보는 사람은 대본을 안 봤다.** 영상 안에서 설명해야 통하는 말은 썸네일에서 안 통한다.

🔴 **왜 신설**: 위 § 의외성 게이트는 *"통념을 깼나"* 를 묻고 § STEP 1-A 는 *"제목과 다른가"* 를 묻는다.
둘 다 통과하면서도 **읽는 사람이 못 알아듣는** 안이 나온다 — 두 게이트 다 «대본을 아는 사람» 기준이라
그 함정을 못 잡는다.
🔴 **실사고 (2026-09-05)**: 「문은 잠갔는데 **1등**입니다」로 안을 냈다가 *"직관적으로 이해되지 않습니다"*
지적을 받았다. **그 회사가 AI 크롤링을 막는다는 사실을 아는 사람만** 읽히는 카피였고, 그건 영상에서 밝힐
반전을 썸네일에 앞당겨 쓴 것이었다. 대본을 쓴 쪽에게는 당연한 말이라 스스로는 안 보인다.

**판정 두 줄 — 3안 각각 채운다. 못 채우면 폐기.**

```
누가 / 무엇을 : [        ]  ← 이 말의 주어와 대상이 «화면에» 보이나?
설명이 필요한가: [        ]  ← 한 문장이라도 덧붙여야 하면 그 안은 폐기
```

| ❌ 폐기 | ✅ 통과 |
|---|---|
| 「문은 잠갔는데 1등입니다」 — 누가 무슨 문을 잠갔는지 화면에 없다 | 「AI 눈엔 **백지**입니다」 — 화면에 빈 화면이 그대로 있다 |
| 영상에서 밝힐 반전을 앞당겨 쓴 것 | 시청자가 **자기 일로 바로 느끼는** 것 |

🔑 **막히면 대본에서 「시청자가 이미 아는 것」을 찾는다.** 그 사람이 이미 겪어서 아는 사실에서
출발하면 설명이 필요 없다.

### 레이아웃 3종 (실측 12장 기준 — 고객사 채널 7 + 한방언니 5 + 가연 2)

| 코드 | 레이아웃 | 언제 이걸로 (대본 성격) |
|---|---|---|
| **A** | 하단 2줄 임팩트 (기본) | **대부분의 롱폼** — 사연·상담·정보. 여러 등장인물/상황극이면 말풍선 부품 켬 |
| **B** | 좌텍스트·우인물 | 1인 인터뷰·경험담·talking-head |
| **C** | 상단센터 (쇼츠 9:16) | 세로 영상·쇼츠 |

### 🎬 포맷 3종 — 롱폼(16:9)은 항상 이 3개를 **동시에** 만든다

> **왜 3개인가**: 실무가 어차피 시안 3장을 요구한다. 카피만 3안 제시하는 것보다 **완성본 3장을 보고 고르는 게 정확**하다(2026-07-30 확정).
> 벤치마크 3채널(한방언니 43만·슈카월드·지식브런치) + 고객사 채널 1개 실측에서 도출.

| 포맷 | 레이아웃 | 구성 | **배경 생성 규칙** | 언제 강한가 |
|---|---|---|---|---|
| **F1 사례형** | A + `--host` | 하단 2줄 + 우측 진행자 + 우상단 역할라벨 (+말풍선) | 인물은 **우측**, **좌하단은 어둡고 단순하게** | 전문가·진행자가 전하는 사연 |
| **F2 장면형** | A (인물 없음) | 하단 2줄만, 배경이 주인공 | 장면 전체를 쓰되 **하단 1/3은 어둡고 단순하게** | 상황·현상 자체가 주제 |
| **F3 인물형** | B | 좌측 텍스트 + **우측 인물 크게** | 인물 **우측 상반신**, **좌측은 어둡게** | 1인 경험담·인터뷰 |

🔴 **"비움"을 프롬프트에 그대로 쓰지 말 것** (2026-07-30 실패). *"좌하단을 비워라"* 라고 했더니 GPT가 **좌측 절반을 통째로 검게** 만들어 이미지가 사라졌다. **"비움 = 없앰"으로 해석된다.**
→ 올바른 표현: *"좌하단은 **어둡고 단순하게 처리하되 장면은 그대로 이어질 것**(가구·창·벽이 어둡게 보이도록). 잘라내거나 검게 칠하지 말 것"*

🔴 **`--role`(역할라벨)은 `--host`(실제 진행자 사진)를 넣었을 때만 쓴다** (2026-07-30 확정).
AI가 생성한 배경 인물에 `(결혼전문가)`를 붙이면 **그 사람이 실존 전문가인 것처럼 보여** GATE 0 ②(기대치 계약)를 깬다. 배경 인물은 상황을 연출한 이미지일 뿐 화자가 아니다.
- ✅ 실제 진행자 사진 업로드 → `--host <url> --role 결혼전문가`
- ❌ AI 배경 인물만 있음 → `--role` **생략**
- 말풍선(`--quote`)도 같은 기준 — 실존 인물의 발언처럼 보이면 안 되고, **상황극 연출**로만 쓴다

🔑 **배경이 템플릿을 따른다 (역순 금지)** — 실측에서 한방언니는 200장이 거의 같은 틀이고, 배경이 **글자 자리를 비워둔 채로** 만들어져 있다. 배경을 자유롭게 생성한 뒤 글자를 얹으면 인물 위에 글자가 올라가 스크림으로 덮어야 한다. **포맷을 먼저 정하고 그 규칙대로 배경을 생성할 것.**

- 쇼츠(9:16)는 포맷 분기 없이 **C 1종**.
- 인물 사진이 없으면 F3는 의미가 약하다 → **F1·F2 2장만** 만들어도 된다.

- 실측 스펙: 글자 = 프레임 높이의 16~18%(대형 2줄), **1줄 흰색 / 2줄(또는 핵심어) 강조색**, 검은 외곽선.
- **강조색은 채널이 정한다.** 이름 붙은 팔레트 3벌(`--acc yellow|red|pink`)이 있고, 그 셋에 없는 색은 **`--acc-color "#RRGGBB"` 로 직접** 준다(`--sub-color` 는 서브카피). 아무것도 안 주면 노랑.
  - 🔴 **새 채널 색을 이 스킬에 프리셋으로 추가하지 말 것** (2026-09-05). 종전에는 팔레트 3벌이 곧 채널 목록이어서 넷째 채널이 오면 공용 파일을 고쳐야 했고, 아래 § 3층 경계가 *"강조색 = 채널이 채우는 슬롯"* 이라 선언해 둔 것과 구현이 반대였다. 지금은 `_base.css` 가 색을 모르고 `--acc-color` 가 유일한 통로다 — 되돌리면 `compose-thumbnail.test.mjs` 의 「_base.css 는 채널 색을 모른다」가 막는다.
- **인물 얼굴 = 화면 높이의 1/4 이상**(상반신 샷이면 자동 충족). 더 크면 더 좋다 — 고객사 채널 A/B 149건에서 얼굴이 큰 쪽이 82% 승(p=0.0009, 그 채널 위키의 규칙 3). 얼굴이 없는 구성은 이 규칙에서 제외.
- 🔴 **「AI가 얹은 글자」처럼 보이는 원인은 네 가지다** (2026-09-05 실측). 발행된 썸네일과 우리 렌더를 픽셀로 대조해 나온 값이다.

  | | 발행 썸네일 | 손 안 댄 렌더 | 고치는 인자 |
  |---|---|---|---|
  | **가로 점유** | 88~94% | 68% | `--title-maxh` 를 올린다 (이 상한이 폰트 크기를 막고 있었다) |
  | **아래 여백** | 5.0% | 9.1% | `--title-bottom` 을 줄인다 |
  | **줄 간격** | 2.1% | 7.6% | `--line-height` 를 좁힌다 (0.90 안팎) |
  | **글자 모양** | 가로로 넓적 | 세로로 섬 | `--font jua` · `gasoek` (넓적한 후보) |

  🔑 **폭을 채우는 것은 폰트 크기가 아니라 «자수»다.** 위 인자를 다 줘도 카피가 짧으면 한계가 있다 —
  실측에서 둘째 줄 9자는 87.7%에서 멎었고, 13자로 늘리자 **90%**로 발행분과 같아졌다.
  글자가 작아 보이면 폰트를 키우기 전에 **카피를 한두 어절 늘려 볼 것.**

  🔑 **카피 뒤가 시끄러우면 `--scrim-h`·`--scrim-o` 로 그라데이션을 키운다.** 밝은 배경일수록 필요하다.

- 🔴 **숫자는 그냥 쓰면 안 읽힌다** (2026-09-05 실측). 한글 제목 폰트는 숫자 글리프가 한글에 안 맞춰져 있다 — 같은 카피를 4종으로 렌더해 잉크 높이를 재니 **전부 한글보다 작았다**(Black Han Sans 86.6% · Gothic A1 87.7% · Noto Sans KR 84.0% · Do Hyeon 90.9%). 윗변도 최대 28px 내려앉아 숫자만 아래로 처져 보인다.
  - **폰트를 바꿔서는 못 고친다** — 넷 다 미달이다. **`--num-scale` 로 키운다.** 실측에서 `1.15` 가 한글과 같은 높이·같은 윗변을 만들었다(발행 썸네일에서 잘 읽히던 숫자가 한글의 96%, 윗변차 3~4px인데 그 값과 일치).
  - 숫자·소수·쉼표·`%` 는 한 덩어리로 묶인다(`4.3%` 가 세 조각으로 갈라지지 않는다).
  - 🔑 **썸네일에서 가장 중요한 글자가 숫자인 경우가 많다.** 카피에 숫자를 넣었으면 이 인자를 확인할 것.
- **프레임 테두리**가 A/B/C 전 레이아웃에 **자동 적용**된다 (`_base.css` `.frame`). 기본은 **흰 2px · 안쪽 여백 14px** — 인자를 안 주면 종전 그대로다.
  - 채널이 테두리를 브랜드 표식으로 쓰면 **`--frame-color` / `--frame-width` / `--frame-inset`** 로 바꾼다. `--frame-inset 0` 이면 화면 가장자리에 딱 붙는다(두꺼운 색 테두리를 쓰는 채널의 모양).
  - 두께는 **캔버스 폭 대비 비율로** 잡을 것 — 렌더는 2배 해상도로 나오므로 `--frame-width 9`(1280 기준 0.7%)가 2560 출력에서 18px이 된다.
- **줄바꿈은 `--title` 의 `|` 로만 정해진다** — 브라우저가 임의로 접지 않는다 (레이아웃 B, 2026-08-20 수정). 그전엔 B의 auto-fit이 폭 넘침을 감지하지 못해(줄바꿈되면 `scrollWidth === clientWidth`) 폰트가 높이 상한까지 커졌고, **2줄 카피가 3~4줄로 갈라졌다.** 카피를 짧게 할수록 폰트가 더 커져 더 갈라지는 역방향 증상이었다. `.title { white-space: nowrap }` 으로 폭 판정을 되살렸다.
- **서브카피 크기 = 레이아웃마다 다름** (2026-07-30 확정, 아래가 실제 동작):

| 레이아웃 | 서브 크기 | 위치 | 한 줄 가드 |
|---|---|---|---|
| **A** | 메인의 **55%** 에서 시작 → 축소 (하한 44px) | 제목 높이에 따라 **자동으로 밀려 올라감** | ✅ |
| **B** | 메인의 **50%** 에서 시작 → 축소 (하한 38px) | 제목 박스 **바로 아래** | ✅ |
| **C** | **58px 고정** | 하단 자막 바 (bottom:150) — 제목과 **의도적 분리** | ✅ (하한 40px) |

  - `_base.css`의 `.subtitle { font-size: 34px }`는 **JS가 안 도는 경로의 폴백**이다. A·B는 JS가 덮어쓴다.
  - ⚠️ 이 폴백을 지우면 안 된다 — 없으면 브라우저 기본(16px)으로 떨어져 안 읽힌다(2026-07-30 실측).
  - **한 줄 판별은 높이로 한다** — 폭(`scrollWidth`)은 넘치면 자동 줄바꿈돼 `clientWidth`와 같아져서 못 잰다.
  - **자동 계산이 안 맞으면 `--sub-size` / `--sub-gap` 으로 값을 직접 준다** (2026-08-20 신설). `--sub-size` 를 주면 「한 줄 가드」 축소 루프를 돌지 않는다 — 사람이 크기를 확정한 것으로 본다.
    - 🔴 **값을 감으로 만지지 말고 렌더 결과를 재서 정한다.** 서브 글자의 아래끝과 메인 글자의 위끝 사이가 **20px 이상**(1280×720 기준)이면 겹쳐 보이지 않는다. 실측 없이 조절하다 235 → 252 → 259 → 264 를 헛돌았다(2026-08-20).

- [ ] 정답/결론을 말하고 있지 않나?
- [ ] 🔴 **비튼 것을 한 단어로 지목할 수 있나?** (주어/동사/장소) — 못 하면 폐기하고 다시
- [ ] 🔴 **금지 리터럴 4종에 걸리지 않나?** (`~했습니다` 결말 서술 / `정답은` / `~가 답입니다` / 대본 결말 복사)
- [ ] 🔴 **제목과 썸네일이 같은 정보를 말하고 있지 않나?** (STEP 1-A ③ 중복 게이트 — 「제목이 말하는 것 / 썸네일이 거는 것」 두 줄을 채웠나. 같으면 폐기)

### STEP 3-B — 렌더 후 눈으로 확인 (생략 금지)

**만들고 끝내지 말 것.** 렌더된 이미지를 실제로 열어보고 아래를 확인한다 — 값이 맞아도 결과가 틀릴 수 있다(2026-07-30에 전부 실제로 발생한 것들):

- [ ] **글자가 배경을 덮지 않나?** — 글자 영역이 세로 35~40%를 넘으면 이미지가 안 보인다
- [ ] **서브카피가 읽히나?** — 너무 작으면 "사례 고정" 역할을 못 한다
- [ ] **인물 얼굴이 글자에 가리지 않나?**
- [ ] **배경 좌측(또는 텍스트 영역)이 통째로 검게 죽지 않았나?** — 프롬프트에 "비움"을 쓰면 GPT가 "없앰"으로 해석한다
- [ ] **한글이 깨지지 않았나?**

문제가 보이면 **값을 감으로 만지지 말고** 원인을 구조에서 찾는다 — 글자가 크면 `카피가 짧은 것`이 원인일 수 있고, 자간이 넓어 보이면 `폰트 굵기` 문제일 수 있다.

**→ 기획 3안을 사용자에게 제시** (안별로 제목/메인카피/서브카피/배경컨셉/갭언어유형). "몇 번 안으로 갈까요? 고칠 부분 있으면 말씀해 주세요."

> 🔴 **완성본도 «항상 3장»이다 (2026-09-05 사장님 확정)** — 기획만 3안이 아니라 **렌더까지 3장을 만들어 제시한다.**
> 한 장만 내면 사장님이 «비교»를 못 하시고, 고르는 대신 고쳐야 해서 왕복이 늘어난다.
> 🔴 **3장은 «같은 카피의 배치 변형»이 아니라 «서로 다른 안»이다** — 카피(회수 장치)가 달라야 3안이다.
> 배치만 바꾼 세 장은 1안을 세 번 낸 것이고, 그건 고를 거리가 없다.

## STEP 4 — 대화 수정 → **카피 확정**
- 사용자가 고른 안 + 수정 요청("2번 메인 더 세게", "서브 짧게") 반영.
- 여기서 확정하는 건 **카피(제목/메인/서브)** 다. 포맷은 다음 단계에서 **3개 다 만들어 보여준다.**

## STEP 4-B — 3포맷 동시 생성 → 실물로 선택 (롱폼 기본)

확정된 **같은 카피**로 F1·F2·F3를 각각 만든다. 포맷마다 **배경도 따로 생성**한다(배경 규칙이 다르므로).

```
카피 확정 → [F1 배경+렌더] [F2 배경+렌더] [F3 배경+렌더] → 3장 제시 → 사용자 선택
```

- 소요: 배경 3회 + 렌더 3회 ≈ **2~3분**, 이미지 생성 3장 비용.
- 인물 사진 없으면 F3 생략(2장).
- 3장을 나란히 전달하고 **"몇 번으로 갈까요? 고칠 부분 있으면 말씀해 주세요"** 로 마무리.
- 선택 후 수정 요청이 오면 **그 포맷만** 다시 렌더(배경 재사용, 텍스트만 교체 시 비용 0).

## STEP 5 — 생성 (배경 + 인물 합성 + 텍스트 오버레이)

### 5-1. 배경 생성 (텍스트 없이 배경만)
🔴 **`tenant_id`를 넣지 말 것** (2026-08-11 신설) — 자동 주입된다. 자칭 `tenant_id`가 내 토큰의 회사와 다르면 그 자리에서 `tenant_mismatch`로 끊긴다(관문 순서 ③ → ④). `ext_generate_image`는 `read_tenant_id`/`write_tenant_id`를 **받지 않으므로** 다른 회사 자산으로 만드는 방법이 지금은 없다.

`ext_generate_image` 호출 — **배경컨셉을 프롬프트로** (채널 위키의 인물 규칙 적용 — 예: "한국인" 강제). **"이미지 안에 글자 절대 넣지 말 것"** 명시. `n: 1`.
- **비율**: 레이아웃 A/B = `aspect_ratio: "16:9"` / 레이아웃 C(쇼츠) = `"9:16"`.
- 레이아웃 B는 인물이 **오른쪽**에 오도록(왼쪽은 어둡게·여백 = 텍스트 공간), C는 인물이 **중앙~하단**에 오도록 프롬프트로 유도.
- 🔑 **포맷별 배경 규칙을 먼저 적용** (STEP 2 포맷 3종 표) — F1=인물 우측·좌하단 비움 / F2=하단 1/3 단순 / F3=인물 우측·좌측 절반 어둡게. **이걸 프롬프트에 문장으로 박을 것.**
- 🔑 **이미지에도 의외성을 건다 — 단, 하나만** (정본 「용어별 정의」 §1-3). 정본이 명시한다: *"카피는 의외성이 잘 녹아있으나 **이미지가 기존 통념과 동일하기에 의외성이 부족**"*. 상담실·대화 무드(신뢰)는 유지하되 **S·V·P 중 한 요소만** 통념과 다르게 한다 — 인물(주어)/행동(동사)/장소(장소) 중 택1.
  - 예: 상담실인데 **한 사람만 정장이 아니라 작업복**(주어) / 마주 앉았는데 **한쪽이 등을 돌림**(동사) / 상담 장면인데 **카페가 아니라 공사장**(장소)
  - ⚠️ 셋 다 비틀면 무드가 무너져 신뢰(정본 §2-A)를 잃는다. **한 요소만.**
- **"썸네일 느낌" = 인물 누끼 + 배경 콜라주** (실측 레퍼런스 12장 공통점). 인물이 배경과 한 장의 사진처럼 자연스럽게 섞이면 **포스터/썸네일 느낌이 사라지고 그냥 사진처럼 보인다 → 금지.** 프롬프트에 *"인물이 배경과 뚜렷이 분리된 누끼 컷아웃처럼 보이도록, 윤곽선이 선명하고 옅은 림라이트/그림자로 배경과 경계가 확실히 구분되는 포토 콜라주·매거진 포스터 스타일"* 을 명시할 것.
- **2개 이상의 배경을 한 프레임에 합성할 때**:
  - 보조(서브) 이미지는 장식용 대비 이미지가 아니라 **썸네일이 전달하려는 핵심 내용·이유를 실제로 형상화**해야 한다 (예: "인구밀도가 본능을 끈다" → 밀집 인파 사진 ✅ / 막연히 대조되는 소재 ❌).
  - 패널 경계는 **얇고 깨끗한 대각선·직선 구분선**(또는 자연스러운 명암 전환)으로 분할 — **종이 찢김 텍스처만 금지**, 얇은 선 분할은 레퍼런스 표준이라 허용. 전체 패널은 동일 웜톤으로 색보정 통일.
- 반환 `image_url`을 배경으로 사용.

#### 🔴 5-1-A. 한글은 프롬프트에 «인용»하지 말 것 — 영문으로 번역돼 그림에 박힌다 (2026-09-05 신설)

> 🔴 **실측 결함 (2026-09-03, 팀 지연)**: 소재의 손글씨를 지키려고 프롬프트에
> 「함께 할 수 있는 사람」을 적었더니 종이 위에 **`the person I want to do life with.`** 라는
> **영문 필기체**로 그려졌다. `ext_generate_image`가 프롬프트를 영어로 번역해 모델에 넘기기 때문이고,
> **인용부호 안의 한글도 함께 번역된다.**
> ⚠️ **「한 번 됐으니 괜찮다」가 성립하지 않는다** — **바로 직전 호출에서는 같은 문장이 멀쩡히 보존됐다.**
> 재현이 들쭉날쭉하므로 **매 호출 확인**해야 한다.

**규칙 3줄**

1. **보존할 문장을 프롬프트에 쓰지 않는다.** 대신 `"글자는 원본 그대로 유지"` 라고만 쓴다.
   화면에 글자가 아예 없어야 하면 `"이미지 안에 글자·문자·간판을 절대 넣지 말 것"`.
2. **응답의 `translated_prompt` 를 반드시 읽는다.** 거기 영문 문장이 보이면 **그 문장이 그림에 그려진다** —
   렌더 전에 알 수 있는 유일한 신호다. 보이면 프롬프트에서 그 인용을 빼고 다시 부른다.
3. **배치만 바꿀 일이면 AI 를 다시 부르지 않는다.** 다시 부르면 글자가 또 변한다.
   PIL 로 픽셀을 옮기면 글자가 변할 수 없다(캔버스를 새로 만들어 원본을 붙이고, 빈 아래쪽은
   맨 아랫줄을 늘려 채우면 책상·바닥 같은 단색면은 티가 안 난다).

🔑 **왜 이게 치명적인가** — 배경에 박힌 글자는 **오버레이가 아니라 그림의 일부**라 나중에 못 지운다.
그리고 한국어 맞춤법·띄어쓰기가 깨진 채로 박히면(실측: `함께 할수`) 채널 신뢰도를 직접 깎는다.
**STEP 3-B 「한글이 깨지지 않았나」 항목이 이 결함의 마지막 그물이다 — 건너뛰지 말 것.**

### 5-2. 인물 합성 (사진 준 경우만)
- 로컬 사진 → 먼저 업로드: **인접한 이미지 스킬**의 `scripts/upload-image.mjs`를 쓴다 — `node <이 스킬 폴더>/../<이미지 스킬 폴더>/scripts/upload-image.mjs "C:/경로/사진.jpg"` (마지막 줄 = URL).
  - 폴더 이름은 설치 형태에 따라 다르다: 팀팩 = `jedi-image` · 개인 = `이미지`. **형제 폴더를 확인하고 실제 이름을 쓸 것** (고정 이름을 박으면 다른 쪽에서 깨진다).
- `ext_generate_image` `mode: "compose"` 또는 `"style_ref"` + `input_images: [{url, role}]` + `preserve_fidelity: true` 로 배경에 인물 합성.
- **"제공 이미지만 사용" 제약이 있을 때도** 사용자가 명시적으로 허용하면 누끼·합성에 `compose` 모드를 써도 된다 (새 장면 생성이 아니라 **제공된 사진의 인물/배경 재구성**이므로). host 패널 크롭(34% 고정폭)으로 인물이 잘리면 **실패로 간주** — 크롭 대신 compose로 자연스럽게 합성할 것.
#### 누끼(투명 PNG)로 인물을 얹어야 할 때 — 크로마키 (2026-08-27 신설)

배경 위에 인물을 **오려 붙인 컷아웃**으로 올리려면 투명 PNG 가 필요하다. 그런데 **팀원 PC 에는 배경제거
라이브러리(rembg 등)가 없다.** 설치를 요구하지 말고 아래 2단계로 만든다.

1. `ext_generate_image` `mode: "edit"` + `preserve_fidelity: true` 로 **배경만 순수 녹색**으로 바꾼다.
   프롬프트에 이 두 문장을 반드시 넣을 것 —
   *"배경은 완전히 균일한 순수 형광 녹색(#00FF00) 단색으로 채운다. 그라데이션·그림자·질감 없이 완벽하게
   평평한 한 가지 색"* · *"인물 위에 녹색 빛이 번지지 않게 한다"*
2. `node <이 스킬 폴더>/scripts/chromakey-cutout.mjs <녹색.png> <누끼.png> [--top 0] [--bottom 0.42]`
   → 인물 바운딩박스로 잘린 투명 PNG. `--top/--bottom` 은 **전신을 상반신으로 자를 때** 쓴다.
   업로드는 5-2 첫 줄의 `upload-image.mjs` 로 하고, 그 URL 을 `--inset` 에 넘긴다.

- 🔴 **AI 가 «작게 구석에 넣어라»를 못 지킨다.** compose 모드로 작은 보조 인물을 배치시키면 사각 스티커로
  잘리거나 **몸 없이 얼굴만 뜬다**(2026-08-27 실측, 3장 중 2장 실패). 크기·위치가 중요하면 AI 합성이 아니라
  **누끼 + `--inset`(HTML 렌더)** 로 갈 것 — 3장이 정확히 같은 자리에 나온다.
- 🔴 **실사 인물에는 흰 외곽선을 두르지 말 것** — *"붙여넣은 티가 난다"* 로 반려됐다(2026-08-27).
  `--inset` 기본값이 «테두리 없음 + 그림자 + 아랫단 페이드»인 이유다. 테두리는 **AI 생성 인물** 쪽에 준다.

- 🔑 **두 인물로 "관계의 거리감·온도차"를 표현할 때** (실측 피드백 2026-07-26, 팀 지연): 작은 원형·액자 인서트로 별도 순간을 끼워넣는 방식(콜라주처럼 어색)보다, **두 인물을 하나의 통일된 배경 안에 나란히 두고 같은 동작을 반대 방향으로 미러링**(예: 둘 다 통화하며 서로 반대쪽을 봄)해 거리감을 **한 장면**으로 보여주는 대칭 구도가 더 선호됨. 시간 흐름형 2장면 몽타주(좌=과거·우=현재)보다 **이 방식을 우선 시도**할 것.

### 5-2-B. 브랜드 로고·실물 얹기 (2026-09-05 신설)

**AI가 만든 무드샷만으로는 「어느 브랜드 이야기인지」가 안 보인다.** 발행된 썸네일을 보면
실제 로고·간판·기사 캡처가 들어가 있는 경우가 많다 — 그게 「진짜 이야기」로 읽히게 만든다.

#### 🔴 로고는 그 회사 사이트에서 받지 않는다

크롤링을 막아둔 회사가 많다. **로고는 위키미디어에 산다.**

```bash
# ① 한국어 위키에 없으면 커먼즈에서 파일명 검색
curl -s "https://commons.wikimedia.org/w/api.php?action=query&list=search&srsearch=<회사>+logo&srnamespace=6&srlimit=4&format=json"
# ② PNG 주소 받기 (iiurlwidth 로 폭 지정 — SVG 도 PNG 로 내려준다)
curl -s "https://commons.wikimedia.org/w/api.php?action=query&titles=File:<파일명>&prop=imageinfo&iiprop=url&iiurlwidth=500&format=json"
```

받은 `upload.wikimedia.org/...png` 주소를 **`--inset` 에 그대로 넘긴다** — 투명 배경 PNG 로 오고,
렌더 백엔드가 그 주소를 직접 불러오므로 내려받아 어딘가 올릴 필요가 없다(2026-09-05 실측).

⚠️ **함정 둘**
- **크기**: `--inset-h` 는 높이다. 가로로 긴 로고는 폭이 크게 잡혀 화면 밖으로 밀린다.
  `폭 = 높이 × (로고 가로/세로)` 를 계산해 `--inset-x + 폭 < 100%` 인지 보고 넣을 것
- **연속 요청**: 위키미디어 API 는 빠르게 여러 번 부르면 **429** 를 준다. 사이에 몇 초 쉬거나
  파일 경로를 한 번에 받아 둘 것

#### 🔴 `--inset` 은 하나뿐이다 — 여럿을 얹어야 하면 한 판으로 만든다

로고를 여러 개 늘어놓아야 할 때(경쟁사 비교·목록 나열 등)는 **`ext_render_html` 로 그것들을
한 장으로 렌더**하고, 그 결과 URL 을 `--inset` 에 넘긴다.

```
로고 URL 여러 개 → ext_render_html(카드 배열 HTML) → PNG URL → --inset
```

- **흰 배지 안에 넣을 것** — 로고 대부분이 검은 글자라 어두운 배경에 그냥 얹으면 안 보인다
- **⚠️ 투명 배경은 안 된다** — `ext_render_html` 은 흰 바탕을 깔아 준다(실측). 배경을 얹을 자리의
  색을 **픽셀로 재서** 그 값을 `body` 배경으로 주면 이음매가 안 보인다
- 표시(빨간 X 등)는 각 배지 위에 `<svg>` 로 겹쳐 그린다

#### 흰 박스 라벨 — 발행 썸네일의 「말풍선」이 이 모양이다

`--quote` 는 흰 글씨에 외곽선만 넣는다. 발행된 썸네일에서 흔히 보이는 **흰 바탕 + 검은 글씨**
말풍선은 **`--tag --tag-style card`** 다(아래 5-3 § 지목 세트). 화살표(`--arrow-to`) 없이 라벨만 써도 된다.

```bash
--tag "분명 막아놨는데?" --tag-style card --tag-x 5 --tag-y 38 --tag-size 46
```

### 5-3. 텍스트 오버레이 렌더 (픽셀 정확 한글)
`compose-thumbnail.mjs`가 base CSS + 선택 레이아웃을 조립해 백엔드로 렌더:
```
node <이 스킬 폴더>/scripts/compose-thumbnail.mjs \
  --layout A \                    # A(하단2줄·기본) / B(좌텍스트·우인물) / C(쇼츠9:16)
  --bg "<배경 image_url>" \
  --title "월 500 노처녀들이|**상향혼**에 빠지는 과정" \   # | = 줄바꿈, **강조** = 색
  --subtitle "확정 서브카피" \                            # 선택
  --acc yellow \                  # 이름 붙은 팔레트: yellow / red / pink (채널 위키의 compose: 줄)
  --acc-color "#f11e8f" \         # 팔레트에 없는 색을 직접 (선택 · --acc 보다 우선)
  --sub-color "#f11e8f" \         #   서브카피 색 (선택 · 미지정 시 팔레트값)
  --frame-color "#f11e8f" \       # 테두리 색 (선택 · 기본 흰색)
  --frame-width 9 \               #   테두리 두께 px (선택 · 기본 2)
  --frame-inset 0 \               #   테두리 안쪽 여백 px (선택 · 기본 14 · 0=가장자리에 붙임)
  --num-scale 1.15 \              # 숫자 크기 배수 1.0~1.6 (선택 · 기본 1 = 폰트 그대로)
  --title-maxh 300 \              # 제목 블록 높이 상한 px (선택 · A기본 250 / B 420 / C 620)
  --line-height 0.90 \            #   줄 간격 0.7~1.5 (선택 · 기본 0.98)
  --title-bottom 26 \             #   바닥에서 띄운 높이 px (선택 · 기본 40)
  --scrim-h 470 --scrim-o 0.96 \  # 하단 그라데이션 높이 px · 맨 아래 진하기 0~1 (기본 360 · 0.92)
  --role 결혼전문가 \              # 우상단 (역할) 라벨 — 진행자 채널 (선택)
  --channel "<채널명>" \           # 우하단 워터마크 (선택)
  --host "<진행자 얼굴 image_url>" \   # A 레이아웃 우측 인물 (선택)
  --sub-size 52 \                 # 서브카피 크기 px (선택 · 미지정 시 메인 비례 자동)
  --sub-gap 60 \                  # 서브카피와 메인 사이 간격 px (선택 · A 기본 18 / B 기본 24)
  --quote "제발 저리가!!@22,14" \  # 인물 위 말풍선, x,y=%, ! 접두=빨강 (상황극, 선택·반복가능)
  --punch 1 \                     # 배경 채도·대비 보정 강도 (선택 · 기본 0=끔 · 1 초과 시 피부가 붉게 뜬다)
  --inset "<누끼 image_url>" \     # 보조 인물 (선택) — 아래 「지목 세트」
  --inset-shape cut \             #   cut=누끼(기본) / circle=원형 액자
  --inset-x 76 --inset-y 46 \     #   좌상단 좌표 %
  --inset-h 400 \                 #   높이 px (circle 은 --inset-size 지름 px)
  --inset-outline 0 \             #   흰 스티커 외곽선 두께 px (기본 0=없음, 실사 인물은 0 유지)
  --inset-tone "sepia(.26)" \     #   장면 색온도 맞추기용 CSS filter (선택)
  --tag "20년차 매니저" \          # 지목 라벨 (선택)
  --tag-style hand \              #   hand=손글씨(기본) / card=명함 배지
  --tag-x 69 --tag-y 26 --tag-size 62 \
  --arrow-to 84,45 \              # 라벨 → 대상 화살표 끝점 % (없으면 화살표를 안 그린다)
  --arrow-from-x 72 --arrow-from-y 36 --arrow-bend -45
```

**지목 세트 (`--inset` / `--tag` / `--arrow-to`)** — 「이 사람이 누구인지」를 화면 안에서 가리킨다.
`--role` 은 우상단 괄호 한 줄이라 **누구를** 가리키는지 못 나타내는데, 이 셋은 그 자리를 메운다.

- 그리는 순서는 **화살표 → 인서트 → 라벨** 고정이다. 화살촉이 인물 뒤로 들어가야 「가리키는」 것처럼 보인다.
- 좌표는 전부 **캔버스 대비 %** 라 레이아웃 C(1080×1920)에서도 같은 인자가 그대로 먹는다.
- 🔴 **라벨은 대상 바로 옆에 붙인다.** 화면 상단에 두면 인물과 따로 놀아서 «누구를 가리키는지»가 안 읽힌다
  (2026-08-27: y 6% → 26% 로 내려서 해결).
- 화살표가 뭉개져 보이면 **너무 짧은 것**이다 — 시작점을 멀리 잡아 곡선 길이를 확보할 것.
- 셋 다 **인자를 안 주면 아무것도 주입되지 않는다.** 기존 썸네일은 영향받지 않는다.
- **레이아웃 자동선택**: STEP 2에서 정한 A/B/C를 `--layout`으로 넘김.
- **강조색·테두리·외곽선·폰트**는 채널 위키의 `compose:` 줄을 그대로 따름(예: `--acc red --stroke 4px --font gothic` / 팔레트 밖 색이면 `--acc-color "#f11e8f" --frame-color "#f11e8f" --frame-width 9 --frame-inset 0`).
- 스크립트 마지막 줄 출력 = **완성 썸네일 image_url**.
- 🔴 **`--punch` 기본은 0(끔)이다.** 켜는 것을 기본으로 하면 지금까지의 썸네일이 전부 달라진다.
  실무에서 쓸 때는 `--punch 1`(채도 1.12 · 대비 1.05)까지만 — 넘기면 피부가 붉게 뜬다.
- 사용자에게 전달: `✅ 썸네일 완성 (레이아웃 {A/B/C})\n{image_url}`

## 채널 위키 (`channels/` — 하위 계층)

> 판단OS `docs/mcp-wiki/<name>.md` 패턴. **채널 1개 = 파일 1개.** 모태(이 파일)는 채널을 모르고, 채널 파일이 값을 준다.

🔴 **이 배포본에는 채널 파일이 동봉되지 않는다** (2026-08-16). 이 스킬은 `tier: shared`라 다른 회사에도
배포되는데, 채널 위키에는 그 채널의 A/B 실측·톤·금칙 같은 **그 회사 자산**이 들어간다. 남의 회사 팩에
따라가면 안 되므로 채널 파일은 **쓰는 사람의 자리**(아래 1번) 또는 **그 회사 전용 팩**에만 둔다.

### 🔎 채널 규격을 찾는 순서 (세 곳 — 2026-09-05 개정: 팀 공용 자리 = 채널 하위스킬)

| 순서 | 위치 | 성격 |
|---|---|---|
| 1 | **`~/.claude/zulgap/channels/<채널>.md`** | **내 로컬 오버라이드.** 여기 있으면 이걸 쓴다 |
| 2 | **채널 하위스킬** — 그 회사 전용 팩의 `<회사>-<채널>-thumbnail` | **팀 공용 정본.** `extends`로 이 파일을 부모로 선언한다 |
| 3 | `<이 스킬 폴더>/channels/<채널>.md` | 공용 팩 동봉분 — **회사명 리터럴 금지**(D-3), 사실상 항상 비어 있다 |

🔴 **2번을 「규격 파일」로 두지 말 것 (2026-09-05 개정 사유)** — 종전에는 팀 공용 규격을
`shared/thumbnail-specs/<채널>.md` 파일로 뒀다. **파일은 `extends`를 달 수 없어** 이 모태가
바뀌어도 아무도 모른다. 실측: 2026-09-05 이 파일이 **304→576줄**로 바뀌었을 때 그 규격 파일의
반영은 **0건**이었고, 부모 변경 검사에 걸리는 채널은 **2개 중 1개**뿐이었다.
채널 규격은 **하위스킬**로 두고 `extends: <이 스킬 이름>` + `parent-checksum`을 선언한다 —
그래야 부모가 바뀔 때 기계가 막는다. 같은 사고가 블로그 계열에서 먼저 났고(2026-08-04) 그때는
**우연히** 발견됐다.

🔴 **하위스킬에 무엇을 담나 — 판정 기준은 「팀원이 몰라서 일을 그르치나」다.**
그림 비틀기 실측 규칙처럼 **제작 판단에 바로 쓰는 것**은 하위스킬에 담는다.
연구 방법론·미해결 질문·A/B 설계법은 1번(개인 자리)에만 남긴다 — 제작자가 안 봐도 되는 것이다.

**셋 다 없으면 채널 위키 없이 진행한다** — 모태(이 파일)의 기본값으로도 썸네일은 만들어진다.
다만 그 채널의 색·톤·금칙이 안 걸리므로 *"채널 위키가 없어 기본값으로 만듭니다"* 라고 한 줄 알릴 것.

**같은 채널이 여러 곳에 있으면 번호가 빠른 쪽이 이긴다.** 1번(로컬)이 2번(하위스킬)을 덮었으면
*"개인 자리의 채널 파일을 씁니다"*라고 **한 줄 알리고** 진행할 것 — 모르는 채 덮이면 나중에 원인을 못 찾는다.

🔴 **새 채널은 반드시 `~/.claude/zulgap/channels/`에 만든다.**
스킬 폴더 안(`<이 스킬 폴더>/channels/`)에 만들면 **다음 자동 갱신 때 조용히 사라진다** — 플러그인은 커밋마다 새 폴더로 통째 다시 받기 때문이다(에러도 안 난다). `~/.claude/zulgap/`은 갱신과 무관한 자리라 안전하다.

- 새 채널 = **파일 1개 추가**. 모태(이 파일) 무수정으로 적용됨
- 🔴 **팀에 나눠 쓰고 싶어도 팩 레포에 커밋하지 말 것 — 그 레포는 공개다.**
  채널 위키에는 A/B 실측·톤·금칙 같은 전략이 들어가서, 커밋하면 경쟁사가 읽는다.
  **레포가 아닌 경로**(사내 공유·비공개 저장소)로 전달한다.
  ⚠️ 2026-08-16에 실제로 이 경로를 통해 한 채널의 위키가 공개됐다가 같은 날 회수됐다.
  넣기 전에 물을 것 — **「이 파일이 경쟁사 손에 들어가도 괜찮은가?」**

### 🔴 새 채널 위키는 「발행된 것」을 재서 만든다 (2026-09-05 신설)

**채널 규격이 문서에 없고 발행물에만 있는 경우가 흔하다.** 사람은 매번 같게 만들면서도 그걸
적어 두지 않는다. 그러니 **묻기 전에 먼저 재고**, 잰 값을 채널 파일에 옮겨 적는다.

🔴 **실사고 (2026-09-05)**: 채널 정본 파일(24KB)에 타깃·톤·제목공식이 다 있는데 **썸네일 규격은
한 줄도 없었다.** 그런데 발행된 9편은 예외 없이 같은 얼굴이었다(색·테두리·줄 수·서브 유무).
그걸 안 보고 만든 3안이 **3/3 전부** 어긋났다.

**재는 순서**

```bash
# ① 발행분 전수 내려받기 (유튜브 예)
yt-dlp --flat-playlist --skip-download --print "%(id)s" "<채널 URL>/videos"
#    → https://i.ytimg.com/vi/<id>/maxresdefault.jpg
```

```python
# ② 픽셀로 잰다 — 「비슷해 보인다」로 끝내지 말 것
#   색       : 테두리·강조어 영역의 최빈값 (JPEG 압축 오차가 있으니 여러 장 합산)
#   글자높이  : 잉크 높이 ÷ 캔버스 높이 (%)
#   윗변      : 숫자와 한글의 윗변 y 차이 — 처짐을 잡는 유일한 축
#   가로점유  : (글자 오른쪽 끝 − 왼쪽 끝) ÷ 캔버스 폭 (%)
#   줄간격    : 첫 줄 아랫변 ~ 둘째 줄 윗변 (%)
#   아래여백  : 캔버스 아래 ~ 마지막 줄 아랫변 (%)
```

⚠️ **강조색 글자를 빼먹고 재지 말 것** — 흰 픽셀만 세면 강조어가 빠져 **가로 점유가 실제보다
20%p 낮게** 나온다(2026-09-05 실측 오류). 흰색 + 강조색을 **함께** 글자로 센다.

**판정** — 9편 중 9편이 같으면 그건 취향이 아니라 **시그니처**다. 한 편만 달라도 피드에서
남의 채널처럼 보이므로 채널 파일에 **고정 규격**으로 적는다.

### 🔒 3층 경계 — 채널 파일이 바꿀 수 있는 것

| 층 | 바꿀 수 있나 | 무엇 |
|---|---|---|
| **① 불변 (모태)** | ❌ | GATE 0 5법칙 · 탑다운/바텀업 · S+V+P · 포맷 3종 · 렌더 파이프라인 · 카피 길이 규격 |
| **② 슬롯 (모태가 선언, 채널이 채움)** | ✅ 값만 | 타깃페르소나 · 톤 · 갭언어 우선순위 · 배경무드 · 인물규칙 · **강조색·서브색·테두리(색/두께/여백)** · 폰트 · 금칙 · 확정 예시 |
| **③ 채널 실측 (채널 고유)** | ✅ 자유 | 그 채널의 A/B 규칙 · 벤치마크 · 함정 |

🔴 **①을 채널 파일이 덮어쓰면 안 된다** — 그래야 "우리 회사 썸네일은 다 이 기준"이 유지된다. 채널이 ①을 바꿔야 할 것 같으면 그건 **모태를 고칠 사안**이다.

## 기준 정본 (이 스킬의 근거 — 필요 시 참조)

- 🔴 **`PROVENANCE.md` 먼저 읽을 것** — 무엇이 살아있는 정본이고 **무엇이 폐기됐는지**가 여기 있다. 특히 「[유튜브]썸네일제작 매뉴얼」(2025-04)의 **명조 폰트·골드 외곽선·공식/연애 채널 구분은 2026-07-30 기각**됐다. 조사하다 그 문서를 발견해도 되살리지 말 것.
- **`channels/<채널>.md`** — 채널 톤·색·폰트·금칙 + 그 채널의 A/B 확정 규칙. 예를 들어 어느 고객사 채널 위키에는 149건 실측 규칙 5개 + 선호 없는 축 1개가 들어 있다. 시안을 여러 개 만들어 고르시게 할 때 어느 쪽으로 기울지 예측하는 데 쓴다. ⚠️ 그중 2건("화면 채우기"·"그림 비틀기")은 **GATE 0과 충돌해 생성 지침으로 채택하지 않았다**(그림 비틀기는 2026-07-30 부분 채택) — 그 절에 이유가 적혀 있으니 반드시 같이 읽을 것.
- 정본 문서: 「유튜브 썸네일 가이드라인」 · 「에이전트 지침 v2 MrBeast보강판」 · 「갭언어 9종」 · 「용어별 정의」
  → **문서 주소(노션 ID)는 `PROVENANCE.md`에 있다.** 본체에 두지 않는 이유 = 이 스킬은 `tier: shared`라 다른 회사에도 배포되며, 내부 문서 주소가 따라가면 안 된다.
- 미스터비스트 부록A(GATE 0 5대 법칙 원문)는 **관리자 PC 전용이라 배포본에 없다.** 법칙 자체는 이 문서 GATE 0 절에 내재화돼 있으므로 파일 참조가 필요 없다.
