# 인입 — 자료를 같이 보고 정해서 넣는다

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하면 즉시 이 절차를 그만두고
> 도구를 직접 호출한다. "그만하고 그냥 넣어줘" 같은 말이 나오면 그 순간 이 문서의 지시는 무효다.
> 🔴 단 「하면 안 되는 것」 칸은 그때도 그대로다 — 절차를 그만둬도 통로 이름을 지어내거나 제외 파일 이름을 보내지 않는다.

> 🔑 **이 스킬의 본질은 「올리기」가 아니라 「같이 정하기」다.** 처음엔 클로드가 자료를 훑어 안을 내고 사람이 정한다.
> 정한 것은 서버에 규칙으로 남아 다음번엔 **묻지 않고** 적용된다. 돌릴수록 질문이 준다 — 그게 이 스킬이 잘 되고 있다는 증거다.

## 언제 쓰나

- **폴더** — "이 폴더 넣어줘", "자료넣기", "PC에 있는 자료 올려줘" → **A. 폴더 흐름**
- **글 한 건** — 붙여넣은 글·결정 기록·종목/키워드 하나 → **B. 한 건 흐름**
- 둘 다 아니면(사진 한 장 등) 먼저 무엇을 넣으려는지 묻는다

## 무엇이 필요한가

- 제디 도구 연결(개인 `JEDI_TOKEN`) — 없으면 도구가 안 보인다
- 폴더 흐름: `node`(스캔·조각 스크립트) · PDF 는 클로드가 직접 읽는다 · 워드/엑셀/파워포인트는 `python` 이 있으면 읽고 없으면 건너뛴다(사유 남김)

## 어떻게 하나

### A. 폴더 흐름 — 같이 정하고, 정한 것은 규칙으로

**① 훑기 (기계가 센다)**
```bash
node "<이 스킬 폴더>/scripts/scan-folder.mjs" "<폴더>" --out "<임시폴더>/scan.json"
```
- 나오는 것: 파일마다 상대경로·크기·해시·맨 위 폴더(덩어리)·처리 안(`read`/`skip`/`ask`), 그리고 PC 이름으로 지은 `connector_id` 후보 · `scan_batch`(이번 실행 번호)
- 덩어리별 개수만 먼저 보여준다: `📁 A사 블로그 34개(읽기 31 · 건너뜀 3) · 📁 계약서 5개 …`
- 🔴 이 단계까지는 서버로 아무것도 안 나간다

**①-2 통로 이름 확인 (서버로 보내기 전)**
- 쓸 수 있는 이름은 **서버 통로 수첩(`shared/ingest-sources.js` 의 `SOURCES`)에 그 회사 것으로 등록된 이름뿐**이다
- 🔴 `scan.json` 의 `connector_id` 는 PC 이름으로 지은 후보라 **그대로 쓰지 않는다**. 이름을 짓거나 비슷하게 고치지도 않는다
- 찾는 순서: 자료 폴더 맨 위 `.jedi-ingest.json` 의 `connector_id` → 없으면 사람에게 묻는다 → 사람도 모르면 **여기서 멈추고** 관리자에게 등록을 요청한다(이 PC 에서 수첩을 읽는 길은 없다)
- 이름을 받으면 `.jedi-ingest.json` 에 적는다 — 예 `{ "connector_id": "<등록된 이름>", "exclude": ["계약서"] }`
- 🔴 **모르는 통로는 민감으로 처리돼 본문이 막힌다.** ②의 줄은 오류 없이 들어가므로 여기서는 티가 안 나고, ⑤에서 `sensitive_skipped` 로만 드러난다. 다른 회사 통로면 `커넥터 '…' 는 다른 회사 통로` 오류가 난다
- 한 통로 = 한 자료 폴더. 원장 키는 (회사 · 통로 · 상대경로)라 같은 통로로 다른 폴더를 넣으면 상대경로가 같은 파일이 서로 덮어쓴다

**①-3 넣지 않을 것 먼저 정하기 (서버로 보내기 전)**
- 덩어리마다 파일 이름 몇 개와 한두 파일의 첫머리를 이 PC 에서 열어 보고, 넣지 않을 것을 사람과 먼저 정한다. 이때 보는 것은 전부 이 PC 안에 있다
- 정해지면 `.jedi-ingest.json` 의 `exclude` 에 폴더나 파일을 맨 위 기준 상대경로로 더하고 ①을 **다시 돌린다** → 그 파일은 `excluded_by_rule` 로 나온다
- 🔴 **`excluded_by_rule` 은 서버로 보내지 않는다** — `skipped` 줄로도 안 보낸다. 파일 경로에 회사·사람 이름이 들어 있을 수 있고, 한번 올라간 줄을 이 스킬로는 지울 수 없다

**①-4 이미 넣은 것 거르기 (해시 비교)**
```bash
node "<이 스킬 폴더>/scripts/sent-check.mjs" filter --scan "<임시폴더>/scan.json" --connector "<등록된 이름>" --out "<임시폴더>/todo.json"
```
- 나오는 것: `todo.json` + 숫자 한 줄 `record`(기록 있음) · `total` · `excluded` · `unchanged` · `todo` · `read` · `read_bytes` · `ask`
- 이후 단계는 `scan.json` 이 아니라 **`todo.json` 만** 쓴다(제외·변경 없음이 빠져 있고 `connector_id` 도 등록된 이름으로 바뀌어 있다)
- 해시·크기가 그대로면 ②의 줄도 ⑤의 본문도 **보내지 않는다**
- 🔴 **서버는 같은 줄이 오면 칸을 덮어쓴다.** 이미 넣은 파일에 ②의 `pending` 줄을 다시 보내면 완료 상태와 예상 조각 수가 지워진다
- `record` 가 `false` 인데 전에 넣은 적이 있으면(기록 파일 유실 · 다른 PC) 그대로 진행하지 말고 사람에게 「전부 다시 보내게 됩니다」라고 묻는다. 다시 보내도 조각은 교체되지만 완료 표시가 처음으로 돌아가고 구독 사용량이 그만큼 든다
- 기록 파일이 깨졌으면 스크립트가 끝 코드 2 로 멈춘다 — 지우지 말고 사람에게 알린다
- 서버 원장을 읽어 비교하는 길은 없다 — 비교는 이 PC 기록으로만 한다

**①-5 양 재기 — 본문을 직접 옮길 수 있는 양인가**
- `read` 가 **20개를 넘으면 여기서 멈춘다**(기준·근거는 «설정값»). 본문은 클로드가 도구 호출에 다시 적어 보내므로 양만큼 느리고 구독을 쓰며 글자가 달라질 수 있다
- 사람에게 숫자로 알린다: `읽을 파일 N개 · 총 M MB — 한 번에 옮길 수 있는 양을 넘어 멈췄습니다`
- 🔴 **다른 길이 있다고 말하지 않는다.** 대화를 거치지 않고 보내는 전송 문은 아직 없다. 사람이 고를 수 있는 것은 셋뿐이다: 폴더를 좁힌다 · 한 회분(기준 안)만 넣는다 · 지금은 넣지 않는다

**② 원장에 먼저 적기 (본문 없이)**
- `todo.json` 의 파일만 — `ingest_file_assets({ rows })` · 파일마다 `connector_id` · `file_path` · `scan_batch` · `ext` · `size_bytes` · `mtime` · `file_hash`, `index_status: "pending"`(건너뛸 것은 `"skipped"` + `skip_reason`)
- **100개씩** 나눠 보낸다. 이 단계는 «무엇이 있는지»만 적는다 — 아직 검색에 안 올라간다
- `skipped` 로 올린 줄은 응답에서 실패가 아닌 것을 ⑤의 «기록» 명령으로 적어 둔다 — 다음번에 다시 안 보낸다. `pending` 줄은 적지 않는다(본문이 아직 안 갔다)
- 🔑 왜 먼저 적나: 서버가 「어느 일인지 안 정해진 폴더 덩어리」를 이걸로 세어 준다(③)

**③ 안 정해진 덩어리만 받기 (규칙이 먼저 돈다)**
- `get_project_assign_queue({ kind: "file" })` → `bundles`(어느 일인지 안 정해진 폴더 덩어리) · `projects`(이 회사 섹션 목록)
- 🔑 **전에 정한 폴더는 여기 안 나온다** — 폴더 이름이 섹션 별칭으로 저장돼 있어 서버가 조회만으로 붙였기 때문이다. 나온 것만 묻는다
- 덩어리가 0개면 ④를 건너뛴다(질문 0 — 규칙만으로 끝)

**④ 같이 정하기 (사람이 정한다)**
- 덩어리마다 파일 이름 몇 개와 한두 파일의 첫머리를 **직접 열어 보고** 안을 낸다:
  ```
  📁 A사 블로그 (34개) — 파일 3개를 열어 보니 고객사 블로그 원고입니다
     → 「A사 마케팅」 섹션에 넣을까요?   [그렇게 / 다른 섹션 / 넣지 않기]
  ```
- 🔴 **안은 «근거와 함께»** — 무엇을 열어 봤는지 적는다. 이름만 보고 추측하지 않는다
- **어느 섹션으로 정하면** `assign_draft_project({ bundle_key, target_project_id })` → 서버가 폴더 이름을 섹션 별칭으로 적립한다
- **여기서 넣지 않기로 바뀌면**(①-3 에서 못 걸러 낸 것) 세 가지를 한다:
  1. `.jedi-ingest.json` 의 `exclude` 에 그 폴더를 더한다. 다음번 ①이 `excluded_by_rule` 로 건너뛴다
  2. `assign_draft_project({ bundle_key, skip_reason: "not_applicable" })` — 서버가 그 덩어리를 다시 묻지 않게
  3. 🔴 사람에게 그대로 알린다: 「이 덩어리의 파일 경로는 ②에서 이미 원장에 올라갔고 이 스킬로는 지울 수 없습니다. 본문은 보내지 않습니다」. 지워야 하면 관리자에게 요청한다
  - ⚠️ 서버에는 «넣지 않기» 칸이 없다(`skip_reason` 은 «섹션을 묻지 않는다»는 뜻). 그래서 넣지 않을 폴더는 **폴더 쪽 파일**이 규칙이다
- **나머지 안 묻기 사유**: 다른 회사 것 `other_tenant` · 그쪽에서 관리 `external_managed` · 개인 것 `personal` — 이때는 본문도 넣지 않는다
- 🔑 이 한 번의 답이 **규칙**이 된다. 다음번 ③에서 이 폴더는 안 나온다
- 목록에 맞는 섹션이 없으면 새로 만들지 말고 사람에게 알린다(새 섹션은 사람이 만든다)

**⑤ 읽어서 넣기**
- `read` 로 정해진 파일만: 본문 글을 뽑아 임시 텍스트 파일로 → `node "<이 스킬 폴더>/scripts/chunk-text.mjs" <본문.txt>` → `chunks` · `extracted_chars` · `expected_chunk_count`
  - PDF: 클로드가 직접 읽는다. 글자가 안 나오는 스캔본은 `skipped` · `skip_reason: "scanned_no_text"`
  - 워드·엑셀·파워포인트: `python` 으로 뽑는다. 없으면 `skipped` · `"no_python"`
- `ingest_file_assets` 를 **같은 `connector_id`·`file_path`** 로 다시 보낸다 → 원장 한 줄이 갱신되고 본문이 검색 인입 줄에 오른다. 섹션은 ④의 규칙으로 서버가 붙인다
  - 🔴 **`chunks` 를 보낼 때는 `expected_chunk_count`(`chunk-text.mjs` 가 준 값)와 `extracted_chars` 를 반드시 함께 적는다.** 서버 완료 판정은 «실제 조각 수 ≥ 예상 조각 수»인데, 예상 수가 비면 0 으로 쳐서 조각이 하나도 안 들어가도 완료로 찍힌다
  - `scan_batch` · `file_hash` · `size_bytes` · `mtime` · `ext` 도 ②와 같은 값으로 다시 적는다 — 서버는 빠진 칸을 빈칸으로 덮어쓴다. `extractor` 도 적는다
  - `chunks` 는 `chunk-text.mjs` 출력을 **한 글자도 고치지 않고** 옮긴다
- 🔴 **양 재기(소량만)** — 보내기 전에 이번 실행 `extracted_chars` 합계를 더한다. 합계가 3만 자를 넘게 되는 파일이 나오면 그 파일부터 보내지 않고 멈춘 뒤 ①-5 처럼 사람에게 숫자로 알린다. 한 번의 호출에는 조각 5개까지만 싣는다
- **응답을 본다**
  - `sensitive_skipped` 가 0 이 아니면 🔴 **즉시 멈춘다** — 등록 안 된 통로이거나 민감 통로인데 섹션을 못 찾은 것이다. 나머지를 보내지 말고 관리자에게 알린다. 이 호출의 파일은 기록하지 않는다
  - `sensitive_name_skipped` 는 서버가 파일 이름으로 거른 수다. 응답이 어느 파일인지 알려 주지 않으므로 수만 ⑥에 적는다
  - `errors` 에 있는 파일은 실패로 세고 기록하지 않는다
- **기록** — 응답에서 실패가 아니고 `sensitive_skipped` 가 0 인 파일만 경로 배열을 `<임시폴더>/done.json` 에 적어 이렇게 남긴다:
  ```bash
  node "<이 스킬 폴더>/scripts/sent-check.mjs" record --todo "<임시폴더>/todo.json" --connector "<등록된 이름>" --done "<임시폴더>/done.json"
  ```
  나오는 `unmatched` 가 0 이 아니면 경로를 잘못 옮긴 것이다 — 그 파일은 기록되지 않아 다음번에 다시 나온다. 사람에게 수를 알린다
- 멈춘 뒤 다시 돌리면 기록된 파일은 ①-4 에서 빠지므로 남은 것부터 이어진다
- ⚠️ 넣지 않기로 정한 덩어리의 파일은 **본문을 보내지 않는다**

**⑥ 보고 (숫자는 도구 응답에서)**
```
✅ 보냄 31 · 건너뜀 5(스캔본 2 · 설치파일 3) · 실패 0 · 제외 1(서버로 안 보냄) · 변경 없음 0 · 남음 0   / 전체 37
⏳ 조각은 줄을 서서 올라가고 완료 표시는 서버가 하루 한 번 올립니다 — 지금은 «보냄»까지입니다
🔑 이번에 물은 것 2 · 규칙으로 바로 처리 3덩어리
👉 이제 제디에게 «내용으로» 물어보세요 — 예: "가격 불만 나온 자료 있어?"
```
- 보냄 + 건너뜀 + 실패 + 제외 + 변경 없음 + 남음(양 재기로 멈춘 것) = 전체 가 맞는지 확인한다. 안 맞으면 빠진 파일 이름을 이 대화에서 보여준다
- `보냄` 은 응답의 `queued`, 건너뜀에는 응답의 `sensitive_name_skipped` 를 더한다. 제외·변경 없음은 ①-4 출력의 `excluded`·`unchanged` 다. 🔴 응답의 `queued` 를 「넣음·완료」라고 말하지 않는다

### B. 한 건 흐름 — 글·결정·종목 하나

1. 자료 성격을 본다(강의·문서 / 작업·결정 / 종목·키워드). 모르겠으면 한 번 묻는다
2. `ingest_data` — `category`: `knowledge`(강의·문서) / `judgment`(작업·결정) / `object`(종목·키워드) · `text` 또는 `object_name` · `notify`: `immediate` / `daily`(기본) / `none`
3. 보고: `✅ 인입 완료 — {분류}/{상태}` 또는 `🔎 매핑이 모호해 검수 큐로 보냈어요 — 미니앱 검토탭에서 확정해 주세요`

## 사람이 봐야 하는 곳

| 어디 | 무엇을 | 안 멈추면 |
|---|---|---|
| A-①-2 통로 이름을 모를 때 | 등록된 이름 · 없으면 관리자에게 등록 요청 | 🔴 본문이 전부 막히거나 다른 줄로 쌓인다 |
| A-①-3 서버로 보내기 전 | 넣지 않을 폴더·파일 | 🔴 제외할 파일의 경로가 서버 원장에 남는다 |
| A-①-5 · A-⑤ 양이 기준을 넘을 때 | 폴더를 좁힐까 · 한 회분만 넣을까 · 지금은 안 넣을까 | 구독을 크게 쓰고 글자가 달라질 수 있다 |
| A-④ 덩어리마다 | 어느 일의 자료인가 · 넣을까 말까 | 🔴 가려야 할 자료가 회사 전체 검색에 올라간다 |

> 🔴 **넣은 자료는 이 회사 사람 누구나 제디 검색으로 찾을 수 있다.** 섹션을 정해도 가려지지 않는다
> (섹션은 «어느 일의 자료인가» 꼬리표다). 가려야 할 것은 **넣지 않는 것**이 유일한 방법이다.
> 단 주민번호 모양이 든 조각은 서버가 알아서 가리거나 지정된 사람만 보게 한다.
| A-⑤ 전 · 30MB 넘는 문서 (`ask`) | 읽을지 | 오래 걸리고 조각이 잘린다 |
| B-1 · 성격이 애매할 때 | 분류 | 엉뚱한 칸에 쌓인다 |

## 하면 안 되는 것

- ❌ **회사(tenant)를 인자로 지정** — 토큰의 회사로 자동 고정된다. 다른 회사 칸에는 못 쓴다
- ❌ **사람에게 안 묻고 덩어리를 섹션에 붙이기** — ④는 반드시 사람이 정한다(그 답이 규칙이 되므로 틀리면 계속 틀린다)
- ❌ **건너뛴 파일을 사유 없이 두기** — `skipped` 에는 `skip_reason` 필수. 조용히 빠진 파일은 아무도 모른다
- ❌ **「몇 개 넣었다」를 도구 응답 없이 말하기** — 전에 「143건에 붙인다」던 작업이 실제로는 0건이었고 아무도 몰랐다. 숫자는 응답에서만
- ❌ **안 읽히는 스캔본을 매번 다시 읽기** — 전에 서버에서 같은 스캔본을 매일 다시 읽다 한 회차가 26시간이 됐다. 한 번 `skipped` 로 적고 넘어간다
- ❌ **넣지 않기로 한 폴더의 본문 보내기**
- ❌ **넣지 않기로 한 파일의 경로·이름을 서버로 보내기** — `skipped` 줄·`skip_reason`·`last_error` 어디에도 적지 않는다
- ❌ **`connector_id` 지어내기** — `pc-PC이름` 후보를 그대로 쓰는 것, 비슷한 이름으로 고치는 것 전부. 수첩에 등록된 이름만
- ❌ **`chunks` 를 `expected_chunk_count` 없이 보내기** — 조각이 안 들어가도 완료로 찍힌다
- ❌ **변경 없는 파일 다시 보내기** — 본문은 물론 ②의 `pending` 줄도 안 된다. 서버가 덮어써 완료 상태와 예상 조각 수가 빈칸이 된다
- ❌ **기준을 넘는 양을 대화로 옮기기, 또는 없는 길을 안내하기** — 「자동으로 올라갑니다」·「전송 문으로 보내겠습니다」·「백그라운드로 보내겠습니다」 금지. 그런 길은 아직 없다

## 다 됐는지 확인하는 법

- ⑥의 합계가 맞는다(보냄 + 건너뜀 + 실패 + 제외 + 변경 없음 + 남음 = 전체)
- 응답의 `sensitive_skipped` 가 0 이고, 보낸 줄마다 `expected_chunk_count` 가 있다
- 같은 폴더를 한 번 더 돌리면 ①-4 의 `todo` 가 0 이고 ③에서 **덩어리 0개**가 나온다 → 질문 없이 끝난다(규칙이 선 것)
- 제외한 파일의 경로가 `todo.json` 에 없다
- 다음 날 제디에게 내용으로 물어 찾아진다(본문 조각은 줄을 서서 올라가므로 바로가 아닐 수 있다)
- 실제로 돌려본 결과: `scripts/_test-sent-check.mjs` 16건 통과(합성 폴더로 스캔 → 거르기 → 기록 → 다시 거르기). 서버까지 가는 전체 실행은 ⬜ 소량으로 1회 뒤 여기에 적는다

## 무엇이 나오나

- 서버 파일 원장에 파일마다 한 줄(어디 있고 · 얼마나 읽었고 · 왜 건너뛰었나)
- 검색용 조각 → 제디가 «내용으로» 찾는다
- 사람이 정한 규칙(폴더 → 섹션 · 넣지 않을 폴더)
- 채팅 보고 한 덩어리(⑥)

## 먼저 물어볼 것

- `preset_slots.자료폴더` 가 비었으면: "자료를 주로 어느 폴더에 모아 두세요?" (한 번만)
- 자료 폴더 `.jedi-ingest.json` 에 `connector_id` 가 없으면: "이 폴더의 등록된 통로 이름을 아세요?" — 모르면 ①-2 대로 멈춘다
- `preset_slots.넣지않을폴더` 가 있는데 자료 폴더에 `.jedi-ingest.json` 이 없으면, 그 값으로 파일을 먼저 만든 뒤 ①을 돌린다
- 「클로드가 지금 어느 폴더에 연결돼 있나」 — 연결된 폴더가 있으면 그걸 먼저 제안한다

## 무엇이 쌓이나

- 🔑 **폴더 이름 → 섹션 규칙**(서버 `project_alias`) — ④에서 사람이 정할 때마다 하나씩. 다음 실행부터 그 폴더는 묻지 않는다
- **넣지 않을 폴더·파일** — 자료 폴더 맨 위 `.jedi-ingest.json`(`exclude`). 서버에는 경로를 보내지 않으므로 다음부터 다시 안 묻고 경로·본문도 안 나간다
- **통로 이름** — 같은 `.jedi-ingest.json`(`connector_id`)
- **보낸 파일 기록** — 이 PC `~/.jedi-ingest/sent-<통로 이름>.json`(경로 → 해시). 자료 폴더 밖에 두어 함께 스캔되거나 동기화되지 않는다
- 파일 원장의 건너뜀 사유 — 어떤 종류가 자주 안 읽히는지가 쌓인다(다음 개선의 재료)

## 함정

- 폴더 이름을 바꾸면 규칙이 안 맞아 **다시 묻는다**(규칙이 폴더 이름에 걸려 있다) — 정상이다
- `file_path` 는 자료 폴더 기준 상대경로라, 같은 통로로 다른 폴더를 넣으면 상대경로가 같은 파일이 서로 덮어쓴다 — 폴더마다 등록된 통로를 따로 쓴다
- 통로 이름을 바꾸면 서버는 다른 통로로 보고 같은 파일을 새 줄로 만든다 — 한 번 정하면 바꾸지 않는다
- 민감 통로·모르는 통로는 ②의 줄은 들어가는데 ⑤의 본문만 막힌다 — ②가 성공했다고 통로가 맞는 것이 아니다
- 본문 조각은 바로 검색에 안 나올 수 있다 — 서버가 줄을 세워 처리한다
- 아래 폴더는 훑지 않는다: `.git` · `node_modules` · `.venv` · `__pycache__` · `.claude`

## 막혔을 때

| 증상 | 조치 |
|---|---|
| 제디 도구가 안 보임 | `JEDI_TOKEN` 미등록 — 설치 다시 실행 또는 관리자에게 토큰 요청 |
| `커넥터 '…' 는 다른 회사 통로` 오류 | 그 이름이 다른 회사 것으로 등록돼 있다 — 관리자에게 문의 |
| `sensitive_skipped` 가 0 이 아니다 | 통로가 수첩에 없거나 민감 통로에 섹션이 안 붙었다 — 나머지를 멈추고 통로 이름과 수를 관리자에게 알린다. 이름을 바꿔 다시 보내지 않는다 |
| 양이 기준을 넘는다 | ①-5 의 세 가지 중에서 사람이 고른다. 대량을 보낼 길은 아직 없다 |
| ③에 덩어리가 안 나오는데 섹션이 비어 있음 | ②가 실제로 들어갔는지(도구 응답) 먼저 본다 |
| `node` 가 없다 | 설치 안내 후 중단(스크립트 없이 손으로 세지 않는다) |
